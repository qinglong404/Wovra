# Wovra × ZCode 借鉴清单（成熟 harness 的内部体验报告）

> 状态：**意图存档（活文档）**——纪律照旧：最终形态可能推翻表述，但
> 表达出来的需求细节一条不少；实现形态、参数等第一现场长出来再定。
>
> 来源：2026-09-07 全天。执行模型（GLM-5.3-flash）在 ZCode harness 里
> 连续工作一整天后的**一手内部体验**——不是读文档的对比，是坐在模型
> 位上被这套 harness 驱动、观察它怎么喂上下文、怎么传递运行时意志的
> 实测记录。效度边界：模型只能验证"进入自己窗口的内容"，ZCode 的
> 线格式与 UI 内部属于合理推断，已逐条标注。

## 0. 一页结论

ZCode 的成熟不在机制密度——它的上下文机制（有损压缩、窗口内全量）
其实比 Wovra 简单粗暴，**Wovra 在历史不可变 + 可展开上严格领先**。
它的成熟在于**通道设计**：运行时对模型有一条自己的话筒（reminder）、
对用户有一条自己的话筒（todo UI / 占比图）、对扩展者有一条钩子
（hooks）。Wovra 的机制更精密，但机制缺少"说话的地方"。

**第一梯队四条**（填真实缺口）：① system-reminder 式的运行时专属
注入通道；② ask_user 选项化（决策升级的人尺寸参考实现）；③ 工作区
指令包（跨项目可用）；④ hooks（Runtime Governance 的用户扩展点）。
**四条已于 2026-09-07 全部落地**（形态决策见各节"落地记录"）。

**别借三条**：传统 todo_write 式平铺清单（计划两层论否决过；注意不指
Wovra 自己的大步/小步 `todo`——那是深度恒 1、验收即清的另一形态）、压缩即历史（Wovra 的
Full 存档 + expand 严格更强）、思考入库（浅折扣下必亏，实测同款）。

## 1. 第一梯队

### 1.1 运行时专属注入通道（system-reminder）

* **观察**：ZCode 的运行时通过 `<system-reminder>` 块向模型注入动态
  信息——技能列表、当前日期、todo 更新提醒、规则变更。关键性质：
  **模型能分清"用户说的"和"运行时说的"**；这些块不是系统提示词的
  一部分，而是动态插进对话流的（效度：块的**存在与作用**是模型一手
  体验；具体插在 wire 的哪个位置属推断）。
* **Wovra 的缺口**：装配第 [3] 段（TaskState / 历史索引 / 文件地图 /
  派发板）全部以 **user-role 消息**注入——运行时在冒充用户说话。
  语义混淆的实害：模型分不清哪些是"用户要的"、哪些是"机制给的"。
* **借鉴后的意图**：运行时的话进**有明确身份标签的独立通道**，与
  用户消息分离。
* **落地记录（2026-09-07）**：OpenAI 协议没有独立 reminder role，
  采用"信封 + 系统提示词声明"——`_runtime_reminder()` 以
  `<runtime-reminder>` 包裹后按 user-role 注入，系统提示词声明该
  约定；任务状态/文件地图已迁移至此通道。
* **受益者**：水位预警、暂存整理完成通知、文件过期警告、将来的一切
  运行时意志——全都多了一个不污染用户语义的说话位置。

### 1.2 ask_user 选项化（决策升级的人尺寸参考实现）

* **观察**：ZCode 的 AskUserQuestion 是结构化的：2-4 个选项、推荐项
  标注、强制有"其他"自由输入、选项可附预览；多选支持。
* **与既有原则的关系**：这不是新原则——`next-stage-intent.md` §7.2
  早已写下"机器把决策空间整理成人尺寸的选项（有什么路、各自意味着
  什么）"。ZCode 是这条原则的成熟参考实现。
* **借鉴后的意图**：Wovra 的 ask_user 支持选项化提问（模型给选项 +
  推荐 + 自由输入兜底）；决策升级（escalations）的人视图渲染同步
  支持"选项 + 拍板"形态——人在 report 里看到的不该是一段描述文，
  而是一组可选的路。
* **落地记录（2026-09-07）**：choices 渲染成字母选项（敲字母拍板）、
  multi=True 多选（逗号分隔）、自由文本兜底；report 升级栏目渲染
  待决策升级真实出现后接。

### 1.3 工作区指令包（跨项目可用）

* **观察**：ZCode 在会话启动时读取工作区级指令（AGENTS.md 一类），
  注入系统提示词——"这个项目怎么跑测试、哪些目录别碰、用哪个包管理
  器"随项目走。
* **Wovra 的缺口**：人设与规则硬编码在 `cli._system_prompt`。换一个
  项目，Wovra 仍然只会"通用助手"那一套——这直接限制它成为通用
  runtime 的野心。
* **借鉴后的意图**：会话启动时读工作区根的指令文件，内容追加进
  系统提示词。与 1.1 的通道分离：指令包是**半稳定层**（随项目
  不变），进前缀。
* **落地记录（2026-09-07）**：文件名定为行业事实标准的 `AGENTS.md`；
  `_workspace_instructions()` 读取追加（缺失静默跳过，超长 8000 字符
  截断），置于系统提示词尾部、env 之前。

### 1.4 Hooks（Runtime Governance 的用户扩展点）

* **观察**：ZCode 支持用户配置的钩子在工具调用前后拦截，钩子输出
  被当作**用户反馈**喂给模型（模型被明确告知这一语义）。
* **Wovra 的缺口**：`_DENIED_PATTERNS` 与敏感确认是**写死的**——
  治理规则只能改代码。V3 §6 已把 Runtime Governance 列为独立方向
  （"Runtime 不可靠 → 反复排查 → 步数膨胀"的因果链），但缺一个
  用户扩展点。
* **借鉴后的意图**：工具调用前/后各留一个用户可配置的钩子位：
  前置钩子可拦截（输出给模型当拒绝理由）、后置钩子可观测。审计、
  禁写区、公司策略全部变成用户的配置而不是 Wovra 的代码。
* **落地记录（2026-09-07）**：形式定为 **Python 钩子脚本**
  `.wovra/hooks/pre_tool.py` / `post_tool.py`（跨平台，stdin 收 JSON：
  tool/arguments[/result]）；前置 exit 0 放行、非 0 拦截（stdout 为
  理由回传模型），后置非空 stdout 作为 [hooks 反馈] 追加；超时 10s、
  出错静默跳过（扩展机制绝不带垮工具）。挂载点在 `_invoke_tool`
  （参数清洗后、执行前后）。

## 2. 第二梯队（细节级，顺手借）

* **权限档位**：信任档预选（全自动 / 写文件要批 / 命令要批）取代
  逐条启发式判断——用户可预期，模型不用猜今天哪种操作会触发确认。
  形态候选：`WOVRA_APPROVE` 环境变量或启动参数。
* **压缩摘要的结构清单**：ZCode 压缩后活下来的内容——用户原话的
  忠实转述、已做决策、当前工作状态、"下一步是什么"——这份清单直接
  抄进 Wovra 批量整理的提示词当**验收标准**（整理产出必须让这些
  全部可答）。
* **Plan mode**：只读探索 + 方案获批后才动工。是"t0 意图快照合著"
  的机制化 embodiment，与"可运行闸门"气质吻合。动工时机：等真实
  使用出现"上来就改错方向"的现场。
* **file:line 可点击引用**：report 与工具结果统一
  `路径:行号` 格式——人从报告跳到代码现场一步到位。
  衔接点：`ui.report_view` 与锚点自愈的回显格式。

## 3. 别借清单（防止向成熟工具学习时丢掉自己的优势）

* **传统 todo_write 不借**：把方法层固化成权威清单，`next-stage-intent.md`
  §3 否决过，理由不变。（口径更正 2026-09-11：否决对象是"平铺清单、
  写时固化判断、按列表逐条 tick"的传统形态；Wovra 自有的 `todo` 大步/
  小步账本已实现且不在否决之列——它的防御正是"不许累积"：深度恒 1、
  验收即清、结构闸门防退化。）留一个心眼：ZCode 的 todo 实际是**UI 可见性
  设备**（渲染给人看）而非上下文权威——若真实使用出现"漂移"失败
  模式，值得重新研究其形态，但那天的前提是失败先出现。
* **压缩即历史不借**：ZCode 的压缩有损且不可逆（实测：一次 sed 的
  输出被压缩后，模型本人无法找回，只能靠用户转述）。Wovra 的
  Full 存档不可变 + expand_history **严格更强**——这是本项目的
  结构性优势，向任何 harness 学习时不得动摇。
* **思考入库不借**：DeepSeek harness 每条思考全量进上下文，在深折扣
  （1/40~1/30）下或可成立，在 GLM 1/3.5 折扣下基座税必亏；且协议上
  回传 reasoning_content 会 400。思考是方法层——"方法不进传递"。

* 1.4 钩子的配置形式（脚本路径 / 声明式配置）与执行时机细节。
* 2 权限档位的档位划分与默认值（候选：WOVRA_APPROVE）。

* ~~优先级建议~~：第一梯队四条 + 二梯队"压缩摘要结构清单"已于

  各自的第一现场。

## 一段话总结

向成熟工具学习的正确姿势不是抄机制——论机制，Wovra 的水位、暂存
生效、块结构都比 ZCode 精密——而是抄**通道**：运行时怎么对模型说话
（reminder 通道）、模型怎么对人给选项（AskUserQuestion）、用户怎么
对项目注入知识（指令包）、扩展者怎么对工具加规则（hooks）。四条
通道补齐后，Wovra 的精密机制才有了说话的地方；而 Full 存档 +
expand 这条领先于 ZCode 的底线，一条都不让。
