# 组织运行时首战：Minecraft 复刻 A/B 实验

> 2026-09-06/07。组织运行时 V1/V1.1 的第一次真实负载。
> A = 单 agent（`WOVRA_SOLO=1`，组织层结构性禁用）；B = 组织分叉
> （spawn_subtask + dispatch_subtask 异步派发 + 事件唤醒）。
> 同一任务书、同一模型："为我还原一个网页版我的世界，越还原越好。
> 如果有不确定的地方请进行联网搜索"。C 组（ZCode 产品基准）未交付
> 数据，缺席。
>
> **效度声明**：n=1、无重复；任务为纯前端观感类（强多模态依赖），
> 任务书不含可自动化验收——观感结论里"模型上限 vs 运行时质量"的
> 归因分不清。本报告的**成本/时间/机制验证**部分不受此影响。

## 0. 一页结论

1. **观感：A 组 0 分、B 组 1 分**，都不可玩（A：材质全部加载不出、
   世界空白、前后按键颠倒；B：世界断成一小块一小块、功能还更少）。
   归因第一：**机器没有眼睛**——全部验证是语法/逻辑层的，观感层
   验证密度为 0，任何运行时都救不了这一类失败。
2. **机制实战全部跑通**（§3 清单）：异步派发、自动唤醒、父驱动
   续派带精确决策、清算合并、待办实验、交叉核验——但净成本
   **等效 4.6×、现金 2.4×、墙钟持平、质量噪音级**。
3. **用户的四条反驳成立**（§5）：上下文不膨胀/并行/交叉验证/
   失败隔离，V3 与市面 commodity 已覆盖——组织层独占资产收缩为
   三项（§6）。
4. **战略结论**：护城河在 Context Management（V3），组织层是期权。
   多 agent 冻结于 V1.2；下一场实验换任务形状（验收可自动化）。

## 1. 协议与事故

* 三组工作区隔离（`WOVRA_WORKSPACE`/启动目录），任务书一字不差。
* 事故一：`set WOVRA_SOLO=1` 在 PowerShell 不生效（`set` 是
  Set-Variable 别名）→ A 组口径被污染重跑。修复：**chat 启动横幅
  自报组织层状态**并写入 session 记录——对照口径由运行时持有并
  当场可见，不靠用户记得设了什么。
* 事故二：用户 Ctrl+C 中断主会话，**控制台级联杀死全部后台子进程**
  （exit_code=3221225786 = 0xC000013A STATUS_CONTROL_C_EXIT）。
  修复：后台进程与 run_command 子进程加 `CREATE_NEW_PROCESS_GROUP`
  （新进程组默认免疫 Ctrl+C；整树停止走 taskkill 不受影响）。

## 3. 机制实战验证清单（全部第一次真跑通）

1. **t0 合著**：主 agent 主动 ask_user"做哪种模式？A 创造·经典
   （推荐）…"——意图快照合著，不是等用户吐计划；
2. **异步派发**：3 块并行后台执行，派发秒回非阻塞；
3. **事件唤醒**（实测）：21:49 系统通知"bg-1/2/3 全部结束（exit 0）"
   → 主 agent 自动接手；
4. **父驱动续派带精确决策**：主 agent 读完子任务产出后，续派指令
   "你的 5 个 JS 已过 node --check、22 项断言全过，剩余工作：写
   README…"——报告帮助修计划的字面兑现；
5. **清算合并**：两个子任务账本并入父任务，历史保留；
6. **待办实验**：子任务主动写出"机器无法自测，请人工目检 30 个
   贴图，watch：透明像素行为，pass：接近原版质感"——do/watch/pass
   结构正确，**人当传感器**被模型主动使用；
7. **交叉核验**：逻辑层 node 实测渲染层 30 个贴图名零缺失、发现
   对方未导出 scene 并适配留痕——独立 agent 互相怀疑，单 agent
   结构性做不到。

## 4. 事故解剖：逻辑层账本为什么是空的

bg-4（逻辑层第二次派发）日志恰好结束在最终回答上、**没有耗时行**：
子进程 2 死于"轮已闭合、成本已记"之后、"收尾补整理"之前——即事故二
的 Ctrl+C 级联（当时无进程组隔离）。结果：代码交付了，账本没更新
（主 agent 只好说"ST-A 还差把账本标记为 done，纯文书工作"）。
修复即事故二修复；自愈路径：重派一轮，organize_backlog 会补上历史账。

## 5. 成本归因（等效 4.6× 的构成）

1. **冷启动税 ×3**：每个子 agent 从零建上下文（读契约、重爬文件、
   缓存爬坡），命中率 73.8-94.5% vs 单 agent 98.3%，等效/步 6-10K
   vs 2.7K——最大单项；
2. **翻译与调度**：主 agent 等效 223K 只产出调度与汇报——翻译不产生
   代码但按全价计费；
3. **接缝与重复劳动**：各块自带的 mock/测试/防呆/接口适配，输出
   +1.8× 的主要来源；
4. **轮边界缓存破坏**：多轮重建装配尾部，命中率 88.1% vs 98.3%。

## 6. 四条反驳与价值主张收缩（用户，2026-09-07）

1. 主上下文不膨胀——**V3 分层装配实测已保证**（A 组 90K 封顶从未
   失控），多 agent 增量为零；它多给的只有"专项 agent 手里是自己
   块的全分辨率"，对调度的脑没意义；
2. 并行——市面 commodity；
3. 交叉验证——有明确验收标准 + 独立审查轮即可大部分替代；
4. 失败隔离——V3 降档本来就在做"无关话题淡化"。

**收缩后组织层的独占资产只剩三项**：账本=报告 + 编制复用（长周期
记忆与连续性，V2 蓝本未建未证）、升级/拍板/待办实验的人机协同通道
（已小规模实证）、父驱动里程碑循环（已跑通第一圈）。

**步数预算的裁决**：15 步硬预算方案被否——数据实证多小轮命中率
69.8%（主 agent 6 小轮）vs 98.3%（大轮），预算税（轮边界重建
×2.7）不划算。改为**里程碑驱动轮**：轮长由父 agent 派发时写明的
检查点定义（"本轮做到 X 可验证就收尾"），步数上限退化为安全网。

## 7. 教训与下一步

1. **任务形状错配**：观感类任务测的是"模型 × 多模态"，不是运行时；
   下一场实验选**验收可自动化**的形状（候选：Wovra 开发 Wovra——
   任务长、测试即验收、块天然独立、dogfooding）；
2. **最大机制缺口 = 眼睛**（headless 截图验证环）：材质/渲染失败
   从"人眼后置验收"变"机器前置自检"。这不是 Wovra 一家的缺口，
   是整类 agent 的盲区，单独立项；
3. 组织层冻结于 V1.2（wake-on-event 为最后一修）；编制制 V2 蓝本
   见 `organization-runtime-v1.md` §13，动工前置条件 = 出现真实
   需要长周期复利的任务形状。
