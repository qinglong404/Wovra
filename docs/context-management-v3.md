# Wovra 上下文管理机制 V3（实验修正版）

> 定位：本文是机制定稿。它不是凭空设计——每一条修正背后都是一次实测
> 打脸或一次实测验证。证据链：11 轮观察性对照（`managed-vs-baseline-11rounds.md`）、
> R11 三代机制实验（`round11-context-experiment.md`）、两组受控多轮实验
> （本文 §1，会话 `8ecd11` managed / `02d81f` baseline，Gradio 项目
> "加 10 个功能"真实任务）。
> 阅读前提：`context-management-explained.md`（机制科普版）。

## 0. 一页结论

实验把我们从三个想当然里打醒，V3 是修正后的定稿：

1. **"截断省 token"是幻觉**——折叠时代 39 次重读、2KB 锁孔时代 11 次
   读取全部沉没；执行期零截断后，同量级任务 3 次读取完成。省下的
   token 会被"重读 + 返工"加倍买回来。
2. **"命中率至上"是错的**——baseline 全量回放命中率高达 99.3%，但
   臃肿基座上的高命中照样贵。正确的优化对象是**基座**：每步等效成本
   ≈ 新增 + 基座/30，命中率只是折扣。
3. **"每轮必整理"是过早优化**——轻轮的整理费（3,118）比轮本身的
   干活成本（2,816）还高；14 轮整理共 98K，把 managed 在等效成本上的
   全部优势吃回去了。V3 改为**水位触发的批量合并整理**。

一句话：**执行期零截断，管理看基座，整理按水位，命中率只做诊断。**

## 1. 实验证据总览

受控实验：同一 Gradio 项目、同一冻结起始文件（1003 行原版页面）、
同一任务书（按清单逐轮实现 10 个功能）、同一模型。A = managed，
B = baseline，会话级 ABBA。

| | A managed（14 轮） | B baseline（15 轮） | B/A |
|---|---:|---:|---:|
| 名义 token | 2,255,448 | 4,966,437 | **2.20×** |
| 等效输入（不含管理） | 377,668 | 475,686 | 1.26× |
| 整理/压缩开销 | 98,111 | 0 | — |
| 含管理的等效成本 | ≈475,779 | ≈475,686 | **≈1.00×** |
| 步数 | 112 | 153 | 1.37× |
| 上下文峰值 | 57,472 | 66,456 | 1.16× |
| 工具报错事件 | 10 | 16 | — |

（更早的 11 轮观察性对照同向：总量 1.49×、纯对话轮 4-5×。）

三条必须诚实说明的背景：

* **本实验是轻中度负载**：上下文峰值只到窗口的 3.0%（A）/ 6.6%（B），
  从未触发压缩线。V3 机制的重度优势（§4）在这轮里只露了头，没充分展开。
* **任务为工具密集型**：大文件反复读写使"轮内工作集"在两侧上下文中
  占主导，稀释了历史携带的差异。
* **n=1、无验收快照**：产出质量靠人工判断（两边最终功能均可用），
  B 多一轮是修 bug 轮（Gradio 6 消息格式 + 端口孤儿）。

## 2. 核心修正：从"命中率"到"基座税"

**公式**：每一步的等效成本 ≈ 新增 token + 基座/30。
（缓存命中的部分按 1/30 计价——`_CACHE_RATE`。）

命中率决定**折扣**，基座决定**税基**。两组实测都验证了这一点，方向
却相反：

* **B（baseline）证明折扣的威力**：R13 单轮 592,560 prompt，命中率
  99.3%，当轮等效仅 ~5K。全量回放的纯追加结构是完美的前缀缓存布局。
* **A 的高峰值轮证明税基的可怕**：R15（B）31 步、上下文 66K、命中率
  96.4%，当轮等效仍 ~118K——96% 的折扣救不了一个臃肿的税基。

**推论（V3 的组织原则）**：当基座涨到一定程度，"破坏一次缓存、把
基座压低"比"维持高命中"更省——压缩/整理本质上就是**主动的、一次性的
缓存破坏**，用它换取之后所有步骤的低税基。何时破坏（§4 触发器）、
破坏后基座压多低（整理质量），才是管理机制真正的决策点。

**对 v2 的修正**：v2 把"上下文布局按变化频率排序、保护前缀缓存"
当核心优化。V3 重新定性：追加式布局值得保留（它便宜），但**不要为了
缓存命中率牺牲信息结构、也不要回避必要的重排**——命中率降级为诊断
指标（§7）。

## 3. 修正后的机制清单

### 机制一：执行期零截断（轮内赦免）——已实现

轮内事件全量进入上下文，不做任何内容剪切。三代机制的实测教训：

| 迭代 | 机制 | 实测结果（同一"加功能"任务） |
|---|---|---|
| 第一代 | 轮内折叠（50 事件软限制） | 39 次 read_file 重读同一文件，40 步上限烧完未完成 |
| 第二代 | 无折叠 + 2KB 安全截断 | 11 次读取每次只见前 2KB，全部沉没 |
| 第三代 | **零截断 + 窗口保底** | 3 次读取（理论最小值），一轮完成 |

截断省下的是 token，赌上的是任务——关键数据被截断时，模型进入
"读 → 失忆 → 重读"死循环。轮内成本由 Event 级安全阈值兜底的时代
已结束，唯一的天花板是模型窗口（见机制二）。

### 机制二：窗口保底（唯一的天花板）——已实现

当前轮估算超过 `context_limit × 90%` 时，最老的事件折叠为索引行
直到回线。轻中度负载永远碰不到（本实验峰值 6.6%）；它是最后手段
而非常规机制。

### 机制三：惰性水位整理（V3 新增，待实现）——替掉"每轮必整理"

v2 规则"轮闭合即整理"的实测账目：14 轮整理 98,111 tok，约 7K/轮；
R2 干活 2,816、整理 3,118——**整理比干活贵**；R1/R6/R10 等轻轮的
整理成本占比过半。V3 规则：

* 轮闭合后**不再立即整理**，未整理轮的原始内容体量进入"整理水位"；
* 水位超过阈值（**参数待定**，见 §6）→ 触发整理；
* 小会话可能全程不触发——整理成本归零，早期不再有负优化。

预期账目：本实验若按惰性触发，A 的 98K 整理开销大部分不会发生
（早期轻轮不整理，重轮才整理），等效成本与管理开销的"精确打平"
（§1 的 1.00×）会被拉开。

### 机制四：批量合并整理（V3 新增，待实现）——降碎片、降次数

触发整理时，**把所有未整理轮一次批量处理**，而不是逐轮处理：

* 调用次数：N 轮 N 次 → 1 次（摊薄）；
* 跨轮去重：模型每轮重复交代的决策/背景，合并索引时天然去重——
  v2 的逐轮整理在 RefinedIndex 和 TaskState 里留下了重复条目；
* 合并意图：多条相邻输入合并成一条 Normalized 意图，索引不再碎片化；
* **可展开性不变**：事件 ID（R{k}-E{nn}）不受合并影响，
  expand_history 仍能精确定位任何一条事件。

分批规则：按**时间相邻**分批 + 批量上限（**参数待定**）——不做语义
相似度判定，那是一次额外的 LLM 成本；会话天然按主题成簇，相邻即相似。

### 机制五：整理就是"主动的缓存破坏"——触发器与基座

机制三的触发水位，本质是在选择**何时破坏缓存**：整理把未整理内容
折叠进基座，之后所有步骤在低基座上跑（税基降低），代价是整理调用
本身 + 整理后首步的缓存重建。这与 baseline 的 80% 阈值压缩是**同一
个决策、两种输出质量**：baseline 折成一段摘要，managed 折成结构化
状态 + 逐事件索引（可展开、可核算）。v2 文档 §6 已注明"80% 只是
baseline 的实验触发阈值"——V3 把两者的触发逻辑统一为水位口径。

### 机制六：文件地图与锚点自愈——已实现

* **文件地图**：降档历史中的文件以"路径 + 写/读轮次"清单注入装配，
  模型精准定位，不再盲目重爬（实测：39 次重读 → 3 次读取）；
* **锚点自愈**：edit_file 未命中时给出最接近内容的行号，成功时回显
  行号——模型一次修正，不再整文件重读（实测一轮 6 次失败的主因）；
* **过期保护**：文件被外部修改后拒绝按旧内容编辑。

### 机制七：后台任务的会话化治理——已实现

后台进程记录启动会话；跨会话查看/停止被拒；会话退出时该会话的
后台进程一并整树关闭（keep_alive 常驻除外）。实测教训：baseline
对照组因"旧服务占端口 + 无归属管理"多烧了一整轮（1.75M tok，
全场最贵单轮）。

### 机制八：命中率降级为诊断指标

命中率仍然每轮落盘（`缓存命中/未命中/等效输入`），但用途变为：

* **诊断**：命中率骤降 = 发生了大规模重读或上下文重排——去查原因；
* **核算**：等效输入是成本口径；
* **不再**是装配策略的优化目标——为了命中率保留臃肿结构，就是
  R15 的教训。

## 4. 三种使用场景的预期账目（V3 生效后）

| 场景 | 特征 | 预期 |
|---|---|---|
| 轻使用（<5% 窗口） | 少量短轮 | 不触发整理：成本 = baseline，无管理开销。**持平或略优** |
| 中使用（5-30%） | 多轮功能迭代 | 水位触发、批量摊薄：整理次数减半以上；基座受控。**等效成本显著优于 baseline** |
| 重使用（多次 >80%） | 数百轮/超大工具输出 | 多次"折叠进基座"：每轮低税基运行；对照 baseline 的无界回放+迟钝压缩，**差距随时间复利** |

（重使用行是推算——合成轨迹回放待做，见 §6。）

## 5. 待定参数（开放问题）

1. **整理水位阈值**：绝对值（如 30K tok）还是基座比例（如 15%）？
   倾向比例——自适应窗口大小。
2. **批量整理上限**：单次整理最多吞多少轮 / 多大输入？防止整理调用
   自己变成巨无霸。
3. **前瞻触发**：是否引入"预计剩余工作量"来决定破缓存时机（§2 的
   完全体）？先用水位观察，有数据再升级。

## 一段话总结

V3 的全部修正来自同一个顿悟：**缓存命中率是折扣，基座才是税基；
执行期的截断是在省折扣钱的同时放大税基。** 所以：执行期零截断、
轮内赦免，让模型看到它该看到的一切；管理的唯一职责是在水位到线时
把基座批量折叠到低位——一次破坏缓存，换取之后每一步的低税基；
命中率从此只用来诊断，不用来讨好。
