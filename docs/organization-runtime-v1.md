# Wovra 组织运行时 V1（多 Agent · 职责划分 · 人机协同）

> 定位：V3（`context-management-v3.md`）解决"**一个**上下文怎么不
> 撑爆"（节点内）；本层解决"应该存在**几个**上下文、各自装什么"
> （节点间）。降档与重组是结构隔离的模拟，多 Agent 是结构隔离本身
> ——事前控制 + 结构性控制，上下文管理在组织维度的最强形态。
>
> 证据链：思想对齐存档（`next-stage-intent.md`，需求七条已逐条
> 核对）、V3 机制基线、行业溺死现场（复刻类单轮测试：功能多而地基
> 碎的模型观感为 0，基础稳的反而胜）、Wovra 自身的三代生长史。
>
> **效度声明（先说清楚）**：本文档封的是不变量，放行的是形态候选。
> 不变量从已验证的 V3 原则推导，封得起；一切实现形态、参数、模板
> 等第一现场（复刻类任务的真实溺死现场）长出来再定。按我们自己的

## 0. 一页结论

1. **分工**：V3 管节点内，本层管节点间。子 agent 的上下文天然
   隔离——是降档调度做不到的物理隔离。
2. **切职责，不切视野**：子 agent 带全局、做一块。裁剪视野是写时
   的排除性判断。这一层因此有三个禁地：**不裁视野、不删部门历史、
   不在人机界面上卡死细节。**
3. **传递纪律防电话游戏**：原始需求逐字下传、逐层只追加；目标
   下传、事实上传、方法不进传递。转述是漂移之源，追加不是。
4. **报告零新增管线**：一次整理，三个视图（模型装配 / 机器层级 /
   人活文档）；层级之间零新增整理调用；新增成本只剩低频综合文档，
   走 organization 账户。
5. **人是根节点**：全权、时间最少。决策权按可逆性划界；系统的
   职责包括补偿人的视野——把决策空间整理成"人尺寸"的选项。
6. **组织与执行都是方法层**：拆/并/解散/升降级随每轮任务运行时
   变更，从不一个决策用到死；执行从最简单长起，功能被实验拉出来、
   不被计划推出来——每一步走得稳，不追求高大楼层。

## 1. 三个角色

| 节点 | 职责 | 不做什么 | 上下文的地位 |
|---|---|---|---|
| **人**（根） | 需求与偏好、不可逆决策、当验证传感器 | 不出步骤处方（命令本质是需求传递） | 视野最小、时间最稀缺——系统的输出要适配它 |
| **主 agent**（总秘书） | 对话、拆分梳理、汇总子报告整理成文档、定期修实施计划 | 不做具体工作、不深入细节 | **全场寿命最长、最贵、最不能被污染**——凡会把细节拉进主上下文的动作必须委派，哪怕活很小 |
| **子 agent**（可再为主） | 带全局视野实现一个职责块；对上汇报、对下再拆 | 不改写上层目标、不越自己的职责块 | 每个上下文有界——递归的目的 |
| **叶子** | 干活 + 维护自己的状态账本 | —— | V3 全套机制的完整载体 |

"主 agent 从不做具体工作"的真正理由不是职级礼仪，是**资产保护**：
主上下文一旦开始装 46KB 源码，整个架构退化回单 agent 旧世界。

## 2. 不变量（封版）

1. **原始需求逐字下传，逐层只追加**——每层附加自己的拆解、约束、
   接口约定，不改写上层的话。防电话游戏；也是重组便宜的原因。
2. **目标下传、事实上传、方法不进传递**——计划两层论的组织版：
   展开层向下流，事实向上流，方法每层自己重算。
3. **信息不切开，职责才切开**——职责拆分附带所有权边界（对齐
   文件/模块边界，防写冲突），不附带信息边界。
4. **排除性判断不做**——不裁视野、解散不删历史、人机界面永不
   卡死细节。
5. **决策权按可逆性划界**——可逆的机器做、留痕供否决；不可逆的、
   方向性的升级到人（与敏感命令确认"默认拒绝"同源）。
6. **每个上下文有界**——递归的最终目的是让任何节点都不撑爆；叶子
   判据（单一职责 + 单上下文装得下 → 叶子）是默认启发而非硬门槛，
   模糊任务先比"继续拆 vs 直接做"的收益，差异不明显就都不亏——
   **不为低 stake 的分叉花决策成本**。
7. **解散 ≠ 删除**——清算 = 状态账本合并回父级，历史原样归档。

（七条全部可从 V3 已验证的原则推导：零截断、原始历史不可变、
排除性判断不做、水位、分辨率调度——所以封得起。）

## 3. 机制基线（意图封版 · 形态待现场）

### 机制一：意图快照（任务级 Normalized 输入）

t0 人机合著：人出需求与偏好，主 agent 出展开（要解决的问题、在意
的细节、边界约束、验收标准、粗路标），人批准。产出物 = 目标展开
层，进 TaskState，逐字下传给每个子 agent。粗路标只当排序参考
（骨架优先），不当承诺。"什么算完成"写时定，"怎么做完"每轮算。

### 机制二：职责拆分（切行动，不切信息）

拆解产物 = 全局需求（逐字）+ 各块目标 + 块间接口与所有权边界
（对齐文件/模块）。子 agent 拿到的是"整个任务 + 只做这块的纪律"，
不是"只有这块的任务"。

### 机制三：报告 = 状态账本（一次整理，三个视图）

```text
            ┌─ 模型视图：装配进上下文（V3 已有，每轮）
一次整理 ──┼─ 机器视图：子任务的 TaskState = 交给上级的报告（只新增读取）
            └─ 人视图：活文档 = 机械渲染（零 LLM 成本）
```

子报告不用写——子任务的 TaskState + 事件索引就是报告；主 agent
读账本，自己的水位管线消化进自己的 TaskState；人视图程序渲染。
**报告水位镜像整理水位**；层级之间不新增整理调用。

### 机制四：人视图（大局默认 · 层层剥开 · 永不卡死）

四栏目：当前状态 / 决策升级 / 里程碑线 / 待办实验。默认只给大局；
细节按事件 ID 一层层剥开（跨任务 expand_history 的人类版）；工具
调用返回这类细节默认不呈现、永远可剥。展开权在视图主人手里——
默认不呈现不是排除。

### 机制五：决策升级与可逆否决

决策升级是状态账本的一等公民：预期 / 现实 / 选项 / 影响面 / 不
拍板的后果（哪些分支停、哪些继续）。内容由整理补丁维护（模型写），
呈现机械渲染（程序做）——语义归模型、体量归机制，原则继续成立。
人拍板 = 一轮新输入；改 goal 走修订留痕（谁改、哪轮、为什么）。
异步友好：人不在场，树跑别的分支，升级在队列里等。

### 机制六：动态组织

拆/并/解散/升降级随每轮任务运行时发生——组织结构属于方法层
（快变量），不是目标层。解散 = 账本合并回父级、历史归档；新部门
入职 = 挂载不可变快照 + 附加父级当前视图。**重组便宜是设计出来的**
（没有转述损耗，所以敢动态）。

### 机制七：生长式执行与人作为仪器

不是 t0 分块施工：最小可跑 → 实验压力 → 长出下一个功能。功能被
实验**拉**出来，不被计划**推**出来（过程自相似：开发 Wovra 的
方法论成为 Wovra 执行任务的方法论）。每阶段自证可用（能跑、能走、
能渲染）——"复刻 Minecraft"例子里胜者的策略成为执行价值观。
机器无法闭环验证时，产出**零基础实验指引**：做什么（可复制粘贴）、
看什么、什么算对、把什么反馈回来——人成为验证闭环里的传感器。
待办实验按水位攒批（人是最稀缺资源，不逐轮打扰）；人不在场该
分支暂停、跑别的分支。

## 4. 成本总账

| 动作 | 走哪条管线 | 记哪个账户 | 频率 |
|---|---|---|---|
| 子任务自己的整理 | V3 水位管线 | organization | 水位触发 |
| 子→主的报告 | 无——读子任务 TaskState | **0** | 按需 |
| 主 agent 消化子报告 | 它自己的 V3 水位管线 | organization | 水位触发 |
| 人视图渲染 / 通知 | 程序机械渲染 | **0** | 随时 / 事件 |
| 综合文档（给人的总结、方案修订） | 主 agent 单次调用 | organization | 里程碑 / 水位 / 人索要 |

**新增管线 0 条，新增整理调用 0 次。** 这一层不跟节点内机制抢饭
吃——它复用同一口锅，只把同一份产出多喂两个消费者。

## 5. 与单 Agent 栈的衔接

```text
          人（根）
           │ 对话 / 报告 / 拍板
     主 agent ── TaskState（自己的，水位整理）
      │ 意图快照逐字下传 + 职责块 + 所有权边界
      ├── 子 agent A ── TaskState（自己的）──┐
      │         └──（可再拆，分形）           │ 上级按事件 ID 钻取
      └── 子 agent B ── TaskState（自己的）──┘
```

**已有、直接复用**：Task 持久化与原子写、workspace 绑定、
TaskState、水位批量整理、expand_history、文件注册表（过期保护）、
ask_user、敏感命令确认、purpose 三分账。

**V1 落地（2026-09-06，用户拍板"先实现第一版，再去采集实验数据"）**：
子任务生命周期四工具（`spawn_subtask` / `run_subtask` / `check_subtask` /
`merge_subtask`——逐字下传、越权防护、三层深度安全栏、子任务运行后
全局绑定归还父会话）、决策升级（escalations）与待办实验（experiments）
进状态账本并接入整理补丁、人视图渲染（`wovra report` 命令，机械渲染
四栏目，零模型成本）。

**V1.1 异步派发（2026-09-06，B 组实测逼出来的）**：同步 run_subtask
把几十分钟的委托塞进了秒级工具调用的接口里——主回合阻塞、终端
黑箱、人被锁死。改为 `dispatch_subtask`：子任务 = 独立后台进程
（`python -m wovra run <子任务id>`，复用后台治理基建：日志落盘 /
增量查看 / 整树停止 / 会话退出清理），派发秒回非阻塞；
**[子任务派发板]** 每轮机械注入装配尾部（进程状态 / 轮次 / 升级与
实验计数）——主 agent 每轮看得见子任务进展；子任务在后台无法提问，
ask_user 自动降级为**决策升级**（写账本、收尾本轮），人的拍板经
`pending_instruction` 磁盘通道随下一次派发带回；WOVRA_SOLO 不被
子进程继承（对照开关只作用于启动它的那一层）。进程隔离让
_bind_globals 归还 hack 彻底消失。

**仍待第一现场**：升级模板字段细化、待办实验指引形态、跨任务
expand_history 粒度（V1 以事件索引行钻取）、组织变更操作
（拆/并/升降级——V1 只有 spawn/merge 两个方向）。

## 6. 第一现场计划

1. **拿溺死现场**：选一个复刻类任务（单轮"复刻一个小游戏/网页
   应用"），现行单 agent Wovra 跑一次，TTFT 首次落盘。预期溺死点
   （上下文膨胀、细节遗忘、验证缺失）只是假设——以真实死法为准。
2. **最小分叉**：从真实死因处长出第一批拆分（预期主 + 2 子起步，
   递归不急）。
3. **全程落盘**：步骤数、上下文峰值、整理费、TTFT、返工事件
   （重读/重做）、升级次数——没有这些，本层一切结论无法校准。
4. **阶段验收**：每一阶段都是好的——具体标准随任务书在 t0 合著
   （写时合法区）。

## 一段话总结

V3 让一个上下文永不撑爆；本层让"存在几个上下文、各自装什么"变成
运行时可持续调整的结构。纪律只有一条，和 V3 同根：**不做排除性
判断**——不裁视野、不删历史、不卡死细节、不预写实现。目标向下流，
事实向上流，方法每层现场重算；整理只发生一次，三个视图各取所需；
人站在根节点上，机器负责把世界整理成人尺寸的决策。第一铲土在
现场：先看单 agent 怎么淹死，再从溺死处长出第一批分叉。
