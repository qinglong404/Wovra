# 块标签定义 v1.1（2026-09-09，采纳 DeepSeek 评审修订）

> 设计原则：
> **标签 = 整理分辨率与内容焦点的指令，不是重要性评分。**
> 模型整理时按标签写——标签决定"写多细、写什么"，模型不做
> "哪些重要"的判断。这消除了"应该怎么写"的思考（org 15K 思考
> 撞输出上限的病根），把详略完全收敛到 Runtime 定的标签上。

## 分辨率分级

| 级别 | 含义 | 对应块/标签 |
|---|---|---|
| 全量 | 原文级，不降分辨率 | 用户输入（轮头 + 用户块） |
| 高 | 结构/设计/差异，写得充实 | 创建 / 重构 / LIVE |
| 中 | 改了什么、为什么、影响 | 修改 / 读 |
| 低 | 结论与原因，细节从简 | 删除 / 只读 |
| 一句话 | 失败事实，一句带过 | 幽灵 / 越界 |
| 结论 | 只写结论 | 保底块 / DEAD |

## 文件块标签 → 整理指令

| 标签 | 分辨率 | 整理时写什么 |
|---|---|---|
| 创建 | 高 | 文件用途、整体结构、核心设计思想（骨架级） |
| 重构 | 高 | 重写动机、与旧版的关键差异、现在的结构（差异是重点） |
| 修改 | 中 | 改了什么实现、为什么改、影响什么 |
| 读 | 中 | 为什么读、读出的关键结论（服务于后续的写/改/删） |
| 只读 | 低 | 文件用途/大致结构；需要细节时重新读 |
| 删除 | 低 | 删了什么、为什么删、最终结论 |
| 幽灵 | 一句话 | 文件不存在，读失败（错误路径测试/误读），无实质内容 |
| 越界 | 一句话 | 尝试访问越界路径被安全拦截，读/删未发生 |

**DEAD 的测试文件例外（v1.1 修订）**：测试/实验文件（如 t1_hello.txt
这类"创建-读-删除"的测试矩阵成员）即使 DEAD，摘要也必须保留——
**路径、操作序列、结果、失败原因**。细节可省，事实不能省："只保留
死亡原因与最终结论"针对的是内容实现细节，不是测试事实（它验证了
什么、怎么验的、结果如何，正是"死亡结论"的一部分）。

**幽灵/越界统一模板（v1.1 修订）**：
`路径：动作；幽灵/越界；结果；无实质内容`。
不细分"读幽灵/删幽灵"；动作重要就保留动作字段，一句带过。

## 文件块整理规则

文件块 = 根据块标签与状态，把块内内容**综合总结成一段话**：

1. **一段话**，不拆条、不堆标签——标签和状态是给整理者的**提示**，
   不是输出内容；输出是连贯的一段叙述；
2. **以生命周期标签为骨架**：创建/重构/修改/读/删除按时间序交代
   这个文件块里文件经历了什么（从哪来、做了什么、结果如何）；
3. **多标签只做覆盖检查（v1.1 修订）**：多个标签存在时（如
   「创建，读，删除」），标签用于确认每项都交代到了，**不作为分段
   格式**——仍按生命周期时间序融合成一段，防止变相堆标签；
4. **辅助工具调用结果的阐述**：块内吸收的工具调用（测试/验证/命令）
   把**结果**融进叙述——"改了 X，跑 pytest 验证通过"这种因果链
   是必须的，不能只写动作不写结果；
5. **按状态决定叙述重心**：LIVE 写清当前有效内容/结构（这是现状）；
   DEAD 收在死亡原因与最终结论；HISTORICAL 保留演化关系与关键原因；
6. **交代清楚这个文件块的内容**——读完这一段，后续轮次的模型应该
   能知道：这个文件在本块发生了什么、现在处于什么状态、有什么可
   复用的事实。

例子（示意，非格式约束）：

    创建：index.html 建立 Three.js 场景容器与 HUD 骨架，三块面板
    （世界/控制台/资产）分区明确；随后 edit 调整了视口高度以适配
    移动端，headless chrome 截图验证渲染正常（DOM 检查通过）。

## 工具标签 → 整理指令（v1.2 修订：执行时按工具性质打标签，归属消解）

| 标签 | 含义 | 整理时写什么 |
|---|---|---|
| 工具 | 本文件块**确定性吸收**了验证/执行类工具（test/build/run 标签命令） | 把块内工具调用并入描述：为什么调用 + 结果结论 |

**归属规则（v1.2，执行时判定，零 LLM）**：

| 工具性质 | 归属 |
|---|---|
| 验证类（test/build/run 标签命令） | 吸收进**最近的文件块** + 打「工具」——它们验证刚做的文件工作，时间邻接成立 |
| 调研类（file 标签命令如 grep/ls/cat/find、web_search、web_fetch、list_files） | 吸收进块但不打「工具」——轮级调研，不归特定文件 |
| 环境类 | 环境块（已有） |
| 账本类（todo/notify/consult） | 吸收但不打标，无描述价值 |

文件块的「工具」只代表"有验证/执行类工具，结果需融入叙述"——语义
干净，调研类工具不再污染文件块（R7 的 t3_unicode 假「工具」实证）。

**已知局限**：不匹配 test/build/run 正则的验证命令（如
`google-chrome --headless` 截图检查）落入 other 类 → 不打标；验证
命令的识别覆盖以 tag_command 六类正则为准。

## 状态后缀 → 详略底线

| 状态 | 整理时写什么 |
|---|---|
| LIVE | 保持当前有效状态——内容/结构写清楚，这是现状，后续工作基于它 |
| DEAD | 只保留死亡原因与最终结论（测试文件按上述例外保事实） |
| HISTORICAL | **v1.1 起暂不落地**——触发条件未定义（move/rename、重构替换、被新文件覆盖、不再作为现状引用），待定后启用 |

## 块类型 → 整理指令

| 块 | 整理时写什么 |
|---|---|
| 用户块 | 全量保存：用户原话 + 意图 + 约束；说明被打断后补充/修正了什么、插在哪段工作之后；与文件块彻底独立，不混写。**只在有文件/环境交互的轮出现**——纯聊天轮（只有保底块）的中途用户补充并入轮头用户输入（需求先于结论），不单独成块 |
| 环境块 | 为什么做环境准备（目的）+ 结果 |
| 保底块 | 助手结论，简练一段；**空保底块合并**（见下） |

## 空保底块合并（v1.1 修订）

连续且无工具调用的纯聊天轮（保底块无「工具」标签）合并为一行，
保留轮号锚点。合并行的标记是**「无法定夺」**，不是"无有效结论"——
纯规则判断不了这些轮的内容价值，它们可能是方案谋划、思想对齐、
疑问答疑、招呼介绍等等，有没有价值由整理模型看内容后判定：

    R1-2：无法定夺
    R9-10：无法定夺

有工具调用或文件交互的轮不合并，保持独立。

## 用户输入（轮头）——沿用之前

👤 用户：原文；🎯 意图：澄清后的意图；📌 关键约束：红线/硬性约束。
用户输入永远是最高关注，全量保存意图+梳理+约束。

## 块顺序

按块内**第一次交互**在事件流中的时间顺序排序；一轮内多次穿插交互
（A 写 → B 写 → A 改）不重排，就按第一次交互的顺序。
