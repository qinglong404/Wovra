# managed vs baseline：11 轮平行会话的实测对照

> 2026-09-05。实验组 A = `20260904-211910-fbd3e6`（**managed**，分层上下文），
> 对照组 B = `20260904-211918-3c87e1`（**baseline**，全量回放 + 阈值压缩）。
> 同一晚、同一作者、同一项目（一个纯前端聊天页面从零建到加功能），
> 两模式平行使用，各 11 轮，数据全部来自 task.json 落盘记录。
>
> **效度声明**：两条对话的内容不同（A 偏路线讨论 + 建页，B 偏页面迭代），
> 这是观察性对照，不是同输入的 A/B 测试。结论的强度来自"同类负载段"
> 的方向一致性（见 §3），而非逐轮数值相等。n=1。

## 0. 一页结论

1. **总量**：A 686,119 tok vs B 1,018,964 tok，**baseline 是 managed 的 1.49 倍**
   （prompt 口径 1.58 倍）。
2. **分化不在"干活轮"，在"历史携带"**：R11 大文件轮两者几乎打平
   （345,665 vs 357,778 prompt，1.02×）——轮内工作集两种模式等价；
   差距全部来自更早轮次的携带方式。
3. **最干净的对照段（R5-R10，两边都是纯对话轮）**：A 的 prompt 合计是
   B 的 **57.4%**，且趋势相反——A 从 32,675 **降到 8,527（−74%，降档生效）**，
   B 从 27,227 **涨到 30,822（+13%，回放累积）**。会话越长，差距越大。
4. **缓存调整后差距更大**：A 的 R11 以 89.8% 缓存命中把 345,665 的
   prompt 压到 45,612 等效输入，A 的 11 轮缓存调整后总量约 **386,066**——
   B/A 变为 **2.64×**（B 的缓存数据未落盘，无法做对称调整，见 §5）。

## 2. 三段解读

### 建设期（R1-R4）：B 的峰值是 A 的 2.9 倍

R4 是 B 的爆点：**单轮 291,683 prompt**。baseline 把此前所有轮次的
大体积工具输出（write_file 的整页 HTML 参数与结果）原样回放，每一步
都在为全部历史付费；managed 的分层把同一轮压到 81,973。单轮 3.9 万 vs
29.2 万——这正是设计文档 §1.4"第 69 轮"预言的形态，第一次在真实
会话里出现。

### 纯对话期（R5-R10）：最干净的同类负载对照

两边这六轮都是"用户输入 + 最终回答"的 2 事件轮（无工具调用），
负载性质相同：

| | R5 | R6 | R7 | R8 | R9 | R10 | 合计 |
|---|---:|---:|---:|---:|---:|---:|---:|
| A prompt | 32,675 | 26,956 | 19,293 | 6,038 | 6,692 | 8,527 | **100,181** |
| B prompt | 27,227 | 27,931 | 28,723 | 29,549 | 30,128 | 30,822 | **174,380** |

A 合计是 B 的 **57.4%**。更重要的是**趋势**：A 单调下降 74%（老轮次
持续降档，每轮只带"状态 + 索引 + 近 2 轮全量"），B 单调上涨 13%
（回放只增不减，直到压缩阈值）。**会话越长，managed 省得越多**——
这不是一次性优势，是复利型优势。

### 重活期（R11）：1.02×，打平——因为这轮两种模式等价

两边都在同一阶段对大文件做无截断的读写（R11 时 A 已废除 2KB 截断，
B 从不截断），轮内工作集天然等价，所以 1.02× 打平。这个"打平"本身
是有效数据：**managed 的省token收益来自历史携带，不触碰当前轮的
工作视野**——干活的成本两种模式一样，账都记在历史头上。

## 3. 缓存经济学

| 数据点 | 命中率 | 等效输入 |
|---|---:|---:|
| A R11（usage 行已落盘） | **89.8%** | 45,612（名义 345,665） |
| B R2（仅终端显示，未落盘） | 59.4% | 20,508（名义 48,162） |

A 的 R11 以 89.8% 命中把当轮名义 345,665 压到等效 45,612（名义的
13.2%）：追加式全量上下文恰是前缀缓存的最优布局，"不截断"与
"缓存友好"互相成全。缓存调整后 A 的 11 轮总量约 **386,066**
（B/A = **2.64×**）。

诚实声明：B 的逐轮缓存未落盘（当时记账无此字段），无法对称调整，
B 的真实成本大概率低于名义值；此缺口已在 2026-09-05 的记账修复中
补齐，下一轮平行会话可直接对照。

## 4. 维护成本：两模式的自举开销同量级

| | 机制 | 观测成本 |
|---|---|---|
| A（managed） | Round 整理（异步） | org=6,115（R10，仅此轮落入账本）+ R11 pending |
| B（baseline） | 阈值压缩 | compaction=5,615（R11） |

管理机制自身都不贵（~6k/会话），问题从来不是"整理贵不贵"，
而是"它换来了什么"——这份对照的回答是：换来 R8-R10 每轮 4-5× 的
差距和会话尾部的复利。

## 5. 威胁效度与下一步

1. **对话内容不同**（最大威胁）：A 的 R8-R10 回答更长（completion
   15,455 vs B 的 6,824），两段对话工作量不等价。逐轮数值只可看趋势，
   不可逐点比较。
2. **B 的缓存数据缺失**：对称的等效成本对照要等下一次双模式平行会话
   （记账已补齐）。
3. **下一步**：固定一份任务脚本，两模式各跑 N 次——把观察性对照升级为
   受控实验；本报告作为现场数据基线留档。
