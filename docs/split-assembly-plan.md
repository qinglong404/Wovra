# 分裂第③步：装配接管 + 路由（设计稿 v1）

> **状态：设计稿，未实现、未动代码。** 目的：动手前把三件事定死——域视图的排序与体量、
> 主 agent 保留什么、子 agent 的身份与约束插在哪；并给出缓存定价、验收标准与回滚方式。
>
> 依据：`cache-layout-intent.md`（不变量与定价）、`context-differentiation-runtime.md`
> （机制三/四、Level 1 三项）、`worklog-20260911.md` §22（材料层落地）/§25（工具层），
> 以及本轮零 LLM 实测（`wovra views`、`scripts/maint_health.py`）。
>
> 前置事实：①②（注册表条目、域视图机械派生）已完成；③ 一直未动，因为**接管与路由必须
> 同批**——装配直接接管等于每轮在中部改写历史字节，正是被判死的 V2 三档滑窗（实测命中率
> 83.7% → 49.9%），且没有路由就没有切换点，主链看不到任何行为变化、只白付一次前缀断裂。

## 0. 一页结论

1. **接管不改变任何字节，除非路由切了视图。** 主 agent 视图 = 今天的装配，逐字节相同
   ——这是最小风险路径，也是验收第 1 条。
2. **切换点只有一个：轮开启时刻。** 轮内绝不换视图（轮内赦免 + 前缀稳定），路由结果
   落在轮上、随轮持久化。
3. **粘滞是钱的问题，不是体验问题。** 默认沿用上一轮视图；只有规则命中（用户消息出现
   某域的文件域路径/文件名）才切。切换 = 一次前缀断裂 = 0.0075 元（已知定价）。
4. **域视图必须分档，否则比现在更贵。** 实测 A-1 域视图 62,152 tok > 现行装配地板
   56,433 tok——因为它一行一块地保留了**整个历史**，而现行装配早就把更早的轮降成折叠档。
   见 §2，这是本稿最重要的发现。
5. **三段排法照办**：`[共享 system] → [历史（本域全分辨率 + 外域一行指针）] → [身份与域卡]
   → [运行时信封]`。稳的在前、变的在后；身份放历史之后而不是 system 里的原因见 §3.2。
6. **开关默认关。** `WOVRA_ACTIVE_VIEW` 缺省 off，行为逐字节等于今天；出问题一条环境变量
   回退，不必 revert 代码。

## 1. 现状基线（零 LLM 实测，2026-09-12）

```

  system 2,809   用户原文 6,969   紧凑 20,468（12 轮）   折叠 16,333（38 轮）
  信封 9,796（账本 6,937 / 文件地图 2,859 / todo 0）
域视图 6 域、395 块、归属完整 True
  A      66 块 / 指针 5 / 约 37,366 tok      A-2    52 块 / 约 17,440 tok
  A-1   222 块 / 指针 5 / 约 62,152 tok      A-2-1   6 块 / 约  7,412 tok
  A-3    47 块 / 指针 5 / 约 22,878 tok      A-4     2 块 / 约  6,324 tok
缓存命中（全历史）：working 94.9% / organization 69.6% / split 73.0%
```

口径提醒：域视图的 `est_tokens` 是**该域全部块的一行式重建**（无分档、含全部历史轮），
与装配的「紧凑 + 折叠 + 信封」不是同一口径——读数字前先对齐口径，别直接相减。

## 2. 关键发现：域视图比现行装配更厚

A-1 单域 62,152 tok > 现行装配地板 56,433 tok。原因不是域视图写胖了，而是**它缺分档**：
`view_for_domain` 对 222 个块一律给一行全分辨率描述，而装配对更早的轮早就只留文件名清单
（§27 的二级折叠：本会话折叠档 38 轮 16,333 tok，折叠前曾是 46,782 tok / 80% 是块摘要）。

**结论（本稿的硬要求）**：域视图进装配时，必须按**该域自己的整理代次**分档，口径与现行
`keep_min = 最新代次 − 2` 一致：

```
本域块  → 最近 keep_min 代：一行式块描述（全分辨率）
        更早代：只留文件名清单 + 一句「N 块已折叠」
外域块  → 一律一行指针（按属主域聚合的块 ID 清单，views.py 已有该机制）
```

不分档 = 按域接管反而更贵（A-1 62K > 现状 56.8K），这是必须先解决的量。

## 3. 装配布局

### 3.1 顺序

```
[1] system 人设（静态，冻结；所有视图共用同一份）
[2] 历史轮次（按轮序；每轮内：本域块全分辨率、外域块一行指针）
[3] 子 agent 身份与职责域卡（稳定尾：同一视图内每轮不变）
[4] 运行时信封（绝对尾部：todo / TaskState / 文件地图）
```

### 3.2 三条理由

* **公共在前、域相关在中、身份在后**：命中 = 从第 0 token 对齐的连续前缀，分叉点越靠后
  能共享的越多。身份若放 system 里，每个视图从第 0 字节分叉，跨视图共享立刻归零；放尾部
  则共享 system 头（实测 1,265 tok ≈ 1%）。
* **身份在信封之前**：信封每轮变、身份不变——不变的必须在变的之前，否则每次状态变化都会
  作废身份段。
* **不指望跨视图共享**：各视图互享仅 system 头。分裂的真收益是**每轮体量**（降 82–84%），
  不是"大家吃同一段缓存"。

### 3.3 域视图的渲染改造（实现要点）

`_render_compact(r)` / `_render_collapsed(r, ledger)` 增加一个 `active_domain` 参数
（缺省 `None` = 主 agent，行为与今天逐字节相同）：

* `active_domain is None` → 现行逻辑，一字不改；
* 否则：本域块走现有行；外域块在这一轮里降为一行指针
  `▸ 外域（A-2，3 块）：R12-B2、R15-B1、R20-B3`——块 ID 必须带全，保底是"不丢指针"，
  细节走 `expand_history` 按块 ID 取回。

排序**保持时间序**（不改成域分组）：时间序下同域的相邻几轮字节完全一致，能与主链共享更长
前缀；域分组语义干净但从头分叉。两方案的前缀长度差要等实现后实测（列为待验项，不预设结论）。

## 4. 路由（机制三漏斗，第一版只做前两级）

```
① 粘滞：默认沿用上一轮的视图（零成本、零判断）
② 规则命中：用户消息里出现某域的 file_domains 路径或其文件名 → 切到该域
③ 判不了 → 留主 agent（不调用 LLM）
```

* **不做 LLM 兜底**：主 agent 视图是全量，落它永远不会错——兜底只是体量优化，不值一次额外
  调用。等规则命中率有数据后再定（列为待拍板项）。
* **不做"接活验 ownership 转走"**：第一版没有转交工具；误路由的代价只是体量没降，不是错误
  结论（主 agent 视图本来什么都有）。
* 路由结果**落在轮上**（`round["active_view"] = "A-1"`），随轮持久化；轮内不重算。
* 用户原文**原封不动**（机制三：主 agent 是路由器不是翻译层）。

## 5. 主 agent 视图 = 今天的装配

`active_view == "A"`（缺省）时，装配路径与今天**逐字节相同**——不开路由、没命中、判不了，
都是这条路径。它同时是兜底：独立思想/未归属块的归宿。

推论：**「接管」本身是可观测行为为零的改动**。所以允许先落地接管（开关关着、行为不变），
再落路由（一次改完 tools 与布局）——这正是 §10 的分步理由。

## 6. 切换点与缓存定价

* 切换只发生在轮开启时刻，一次切换 = 一次前缀断裂 = **0.0075 元/批**（已知定价：净
  18,830 tok @ 未命中 0.4 元/M，见 worklog §19）。
* 粘滞轮**零额外成本**：同一视图连续多轮 = 追加式增长，与今天同命中率（90%+）。
* 因此核心工程指标是**粘滞率**：目标 >80%（用户话题本身不常跳）。若实测粘滞率低，说明
  规则太敏感（关键词误命中），应先收紧规则而不是怀疑架构。
* **不做**"切换时顺手整理"：整理有自己的触发线（体量 + 宽限 + 最小间隔），两条线不合并，
  免得把一个可观测机制变成隐式二合一。

## 7. tools 数组

* 所有视图共用**同一份** tools 数组（core.py 纪律：tools 恒定，一差分叉即整段前缀作废）。
* 第一版**不加** `view_context` 之类的模型侧工具（已拍板）；域卡里指路：
  「外域细节走 expand_history 按块 ID 取回」。
* 将来若要加转交/查看工具，**必须与路由同一次改完**（只付一次分叉价）。

## 8. 观测与记账

* 每轮 usage 行加 `view=A-1`（切换频率、粘滞率从账本即可算）。
* `rounds[i]["active_view"]` 落盘 → 可离线对账"这一轮由谁接活"。
* 仪器：`scripts/maint_health.py` 增一节「视图」——当前视图、各视图体量、切换序列与粘滞率。
  （仪器已存在，加一节即可，不新写脚本。）

## 9. 落地顺序（三步，每步可独立验收）

| 步 | 内容 | 可观测行为变化 | 风险 |
|---|---|---|---|
| **1** | 装配支持 `active_view`：域视图分档（本域紧凑/更早折叠 + 外域指针）、身份与域卡段、开关 `WOVRA_ACTIVE_VIEW` 默认 off | **无**（off 时逐字节等于今天） | 低：纯新增路径 |
| **2** | 路由（粘滞 + 规则命中）+ 落盘 `active_view` + 观测节；打开开关 | 有（命中时体量降） | 中：切换即断裂，需实测粘滞率 |
| **3** | 按实测决定：LLM 兜底 / 转交工具 / 域内再分裂（机制四允许子 agent 到达自己水位时再裂） | 有 | 低，且可再议 |

步 1 与步 2 可合并为一次发布（若坚持"同批"的字面口径）；分成两次的好处是步 1 出问题时
连开关都不用碰。

## 10. 验收标准（可检验，不是自述）

1. **等价性**：`WOVRA_ACTIVE_VIEW=off` 与改动前，对同一会话同一轮装配的 messages 序列
   **逐字节相同**（哈希比对）。
2. **降量**：路由到 A-1 时，装配体量 ≤ 今天的 70%（目标值，实测后校准）；且本域块全分辨率、
   外域块指针在场（每个外域块 ID 都能在指针行里找到）。
3. **不丢块**：`verify_completeness` 仍 True；折叠档口径与现行 `keep_min` 一致。
4. **缓存**：粘滞轮命中 ≥90%；切换轮只付一次断裂；切换次数与用户话题切换次数一致，
   不存在"每轮都切换"。

## 11. 回滚

* 步 1：删代码路径或 `git revert`（默认关闭，无行为影响）。
* 步 2：`WOVRA_ACTIVE_VIEW=off` 一行环境变量即回到今天；再不行 revert 提交。
* 无数据迁移：`active_view` 是新增字段，旧轮缺该字段视为 `A`。
