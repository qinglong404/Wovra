# Todo 大步/小步工具 · 设计稿（未实现，待批）

> 2026-09-08。背景：早期以"计划两层论"否掉 todo 工具（计划赶不上变化，
> 工具化即僵化）。大步/小步制以**计划深度恒等于 1** 化解——工具里永远
> 只存"当前大步 + 它的小步"，下一大步在当前大步验收通过后才允许写。
> 计划只保留一步深度，永远不与长期现实发生偏差累积。
> **状态：已实现**（同日）。开放问题已决：工具名 = `todo`；人工验收
> 分两型（阻塞型停轮等反馈 / 非阻塞型 defer_check 挂起累积、大步收尾
> 一次性呈交、未决转 experiments 不搁置）；小步跨轮持久（绑死大步
> 生命周期，关大步即清）。

## 1. 概念

| 层 | 是什么 | 生命周期 |
|---|---|---|
| **大步**（milestone） | 一次可验收的增量：最简单可跑方案 → 验收通过 → 才写下一大步 | 跨轮持久，验收后关闭 |
| **小步**（step） | 大步内的常规工作清单 | 绑死大步：开大步时建，关大步即清 |

粒度判据：一个大步 = 一次可验收的增量。太大（"重写整个项目"）说明该拆；
太小（= 一条小步）说明该并。验收口径来自用户或 `task.acceptance_criteria`。

## 2. 状态模型（`task.todo`，随 task.json 持久化，深度恒为 1）

```json
{
  "milestone": {
    "goal": "多会话版：左侧列表 + 新建/切换/删除",
    "acceptance": ["刷新后会话保留", "删除当前会话回落到相邻会话"],
    "started_seq": 3
  },
  "steps": [
    {"text": "sessions 数据结构与 localStorage 读写", "done": true},
    {"text": "切换/删除交互 + 移动端抽屉", "done": false}
  ],
  "history": [
    {"goal": "单文件聊天页初版", "evidence": "node tests/run.js 全绿",
     "closed_seq": 2}
  ]
}
```

## 3. 工具形态：单工具多动作（常驻工作工具）

模型主动调用的**工作工具**（非维护提交工具；常驻 → tools 数组恒定，
缓存纪律不变）：

| 动作 | 语义 | 守卫 |
|---|---|---|
| `start_milestone(goal, acceptance[])` | 开新大步，acceptance 必填，**硬上限 3 条**（F 组实测 4-6 条打包 → 轮被拖大 → 整理批次撞等待） | 已有开启中的大步 → 拒绝（深度=1 强制）；acceptance > 3 → 拒绝并要求拆成下一大步 |
| `add_step(text)` / `check_step(text)` / `drop_step(text)` | 小步增删改 | 无开启中的大步 → 拒绝 |
| `verify_milestone(evidence)` | 关大步：证据必填（测试输出/人工确认） | 自动追加 TaskState.completed、清空小步、提示写下一大步 |
| `drop_milestone(reason)` | 诚作废（计划可证伪，记录死亡原因） | — |
| `show()` | 读当前状态 | — |

## 4. 集成点（不另立第二本账）

* **TaskState 单一事实源**：`verify_milestone` 自动把大步摘要 + 验收
  证据追加进 `completed`——todo 是 TaskState 的结构化前哨。
* **里程碑驱动轮（2026-09-08 晚落地，D 组实证驱动）**：`verify_milestone`
  即**轮边界**——闭合当前轮并开新轮续写同一回合（新轮 user_input 带
  运行时说明；工具结果告知模型"轮次已闭合并开启新轮"）。检查点 =
  轮闭合，水位整理才有轮可整理（D 组 229 步巨型轮全程无闭合，
  grace 双条件修正后巨型轮达水位也照常整理）。
* **runtime-reminder 尾部**：展示"当前大步 + 小步进度"——跨轮/中断后
  续跑的工作记忆。
* **机制二历史线**：大步边界 = 类内叙事的**章节标记**——干活时由模型
  声明，整理时免反推（DeepSeek"逻辑阶段归组"的正解）。
* **轮 ↔ 大步映射（2026-09-09 落地）**：`verify/drop_milestone` 在
  history 记录 `started_seq` + `closed_seq`（旧数据缺 started_seq 时
  按"上一个大步闭合轮 +1"推断，区间不重叠）；整理/分裂指令自动注入
  `[轮↔大步映射]` 段——同一大步的轮通常同属一个功能域，辅助现状归属
  判断。
* **现状清单检查点**：大步验收 = 现状可能变化的时刻，与分裂分析的
  现状清单更新天然对齐。

## 5. 纪律

1. 深度恒 1：永不维护长程计划。
2. 入口/出口都是证据：acceptance 必填、evidence 必填，禁止自述完成。
3. 诚实作废：计划可证伪，废弃要留原因。
4. **acceptance 有下游后果（2026-09-09 里程碑驱动轮落地后生效）**：
   verify_milestone 即轮边界——验收标准的粒度质量直接决定轮粒度与
   整理质量（整理以轮为单位出块/归属）。大步按"可验收的增量"划分，
   acceptance 写可检验的口径，不写"做好做完善"这类不可判定的空话。
5. **大步收窄硬约束（2026-09-09 F 组数据驱动）**：acceptance 1-3 条，
   超 3 条拒绝。F 组 5 个大步全部 4-6 条打包（如"核心玩法：物品栏
   图形化+挖掘进度+粒子+音效+存档+视角"），单轮事件 367 个、上下文
   堆到 325K、整理 6 次全 pending——大步宽度就是轮宽度与整理批次
   大小，宁可小步快跑。

## 6. 开放问题（已决，见头部状态）

* `verify_milestone` 是否需要用户确认——倾向：机器可验的走测试证据，
  人工验收类大步走 experiments 通道（机制五"人当传感器"）。
