# 上下文模型 v4：共享叙事 + 文件归属（草稿，待拍板）

日期：2026-09-16
状态：**讨论稿**。核心口径已与用户对齐，未决项列在 §12，拍板后再动代码。
驱动案例：会话 `20260916-090533-964be8`（GAIA 评测 + 提示词审查，9 轮、11 个活性文件）。

---

## 0. 一句话

**取消"重组"**：历史不再按域重切，只有**一份共享的压缩叙事**（每轮一段话，执行者自己写），
外加**域私有的细节**；唯一需要归属的是**文件**，而文件归属是机械的。
分裂从此不再"重切历史"，只变成"分配文件 + 建 agent"。

---

## 1. 分裂要解决的是什么（先定目标，再定机制）

**不是省 token，而是"注意力别被污染"**：解 A 问题时带着 B 的一堆内容，真正的代价是
**串味**——把 A 的框架和结论套到 B 上。

本场是活标本：模型一边捧着 GAIA 评测那一摊（九个脚本、260 个事件、跑批结果），
一边被问「你是不是不知道自己是 Wovra」；它把「测试 Wovra」理解成「搭 harness 去测那个平台」。
省 token 只是顺带收益。

由此，判据从"内容重不重要"改成"**它对当前问题是什么角色**"：

| 角色 | 判据 | 处理 |
|---|---|---|
| 前提 | 丢了这问题本身读不懂（R1–R3 之于 R4–R9 的质问） | **必留**（可压成一行结论/指针） |
| 参考 | 丢了不影响理解、影响结论质量 | 留**指针 + 结论**，细节按需取回 |
| 无关 | 既非前提也非参考 | 不留内容，**但留存在性** |

> **不对称原则（本设计的地基）**：**内容可以丢，存在性不能丢**。
> "不知道它存在"会让模型重新发明轮子、或得出"网上没资料"式的错误结论——
> 我们在检索那条线上刚踩过同一个坑。内容是可恢复的，存在性不可恢复。

## 2. 现状为什么不行（六条，均可复现）

1. **两套真相源**：模型的语义树 vs 代码的机械判据链；同一份历史在两个面板走不同规则 →
   "结构树没问题、上下文不对"是结构决定的，不是显示 bug。
2. **兜底桶承担"未知"**：判据链上有四条路径落到主 agent（环境块、文件未认领、
   保底块跟轮、其余），本质都是"不知道给谁就给它"。N 个域之后它把分裂的收益反向吃掉
   （本场 Main 装配 14,415 tok = 基准 100%）。
3. **"主 agent 不许有文件"这条检查被替换成了更窄的保证**：`maintenance.py` 里
   "事后校验 + 抛错中止"退场，改由 `_bind_files_by_path` 的**构造保证**承担——而那条保证
   只覆盖**活性文件**，只读/幽灵文件走 `history_files` 另一条路，`views.ownership` 的
   "文件块没域认领就跟轮走"是**渲染期**兜底，不在保证内 → 本场 R1 的幽灵块就进了 Main。
4. **判据是表层特征**（路径前缀、轮标记），而归属本质是语义的（能不能独立接活、能不能
   独立验收、上下文是否连续）→ 一个职责被按文件碎成四个域（数据与筛选/判分与重判/
   执行与调度/报告与文档），一条语义线被劈成两半。
5. **块切分按文件、不按话题**；用户块只有一个落点 → "一轮拆给几个 agent、用户发言两边都留"
   在当前数据模型里做不到。
6. **没有"树错了"的机械信号**：唯一的覆盖缺口检查被"兜底给主 agent"静默吸收——
   树 8 节点对 agent 2 个，系统自己是沉默的。

**共同病根**：算法之所以要算"块归谁"，纯粹是因为要给每个域**重新切一份历史**。
**取消重组，上面六条一起消失。**

## 3. 新模型

### 3.1 三层

| 层 | 内容 | 谁带 | 变化频率 |
|---|---|---|---|
| **常量** | 工作区、解释器、shell、任务状态 | 系统提示词/信封，全体 | 几乎不变 |
| **共享叙事** | **每轮一段话** + 执行者 + 轮次 | 全体（逐字节相同） | 每轮追加一段 |
| **私有细节** | 自己的工具结果、分析、文件全文、决策 | 只有该域 | 该域干活时才长 |

### 3.2 写：每轮一段话（轮闭合后尾部追加）

**形态**（实测依据 §4.1）：`装配快照 + 尾部追加一条指令 → submit_round_notes`。
纯追加实测命中 99.4%，单次只付 225–235 tok 级新增——所以写的边际成本 =
最终回答 + 指令 + 产物，**不重付内容、也不破坏前缀**。

- **粒度**：一轮 → 一段（一句话，关键数字/路径原样）；**长短看步数看细节，不强求统一**。
  `join_with` 的交棒轮**每棒一条**（各带自己的执行者，按 `event_owners` 的边界切）——
  一轮可以有多个执行者，段落粒度实际是"交棒单元"：**每个参与者只写自己那一棒**
  （指令里写明"别的参与者的部分由它们各自追加"）。**渲染规则**：该轮有多条（多棒）或执行者
  非 Main 时才显示 `〔执行者〕`（pre-split 全是 Main，逐轮挂标签只是噪音）。
- **谁写**：**执行者自己写**。调用输入是轮末装配快照，本轮事件原样在其中，
  且尾部追加的指令是唯一新字节 → 最高保真、最低成本。
- **字段表**（3 项代码填、1 项代码强制）：`执行者 / 轮次`（代码盖章——**不让模型自报身份**：
  本会话的病根就是身份错位，让它自报等于给它一次写错的机会；追加档 = 正在追加的这个 agent，
  批次档 = 该轮 `active_view`）、`一句话叙事`（模型）、
  `失败与坑`（**代码强制**：本轮有 exit_code≠0 / `op_failed` / 幽灵与越界拦截 → 必须非空，
  否则带诊断重发一次，仍不合格落代码骨架段并留痕）、`账本增量`（约束/坑/拍板/待决，可空）。
  原话不压缩——**👤用户原话由代码逐字承载**；`🎯意图` 降级为"执行者怎么读这条要求"，
  不冒充用户意图（本场"测试 Wovra→搭 harness"的方向错误就出在这一层）。
- **锚（必须有，且由代码给）**：每轮附一份**动作清单**——代码从事件里机械抽出（工具名×次数、
  读过/写过/删过的文件、非零退出的命令、有无 final_answer），模型只负责把清单说成一句话。
  **2026-09-17 实测教训**：为了把产物压到 1.8K 而删掉分块地图之后，"每轮一句话"立刻开始
  张冠李戴——5 个纯对话轮（零工具调用）里有 3 条的产物在描述工具工作（"启动 4 题重测跑"
  "停掉 bg-1（exit_code=-9，进程树强杀）""逐行审查 `prompt.py` 并交付 349 行报告"），
  而那些工作在别的轮。旧契约里"块 ID 与内容必须严格一一对应"那句不是啰嗦，它是**位置锚**；
  锚删了，模型就按"这几轮大概讲了什么"重新分配。
  **补锚重跑**：告警 13 → 3（剩下 3 条是粗规则误报：`README.md/AGENTS.md` 被当成一条路径、
  `runner.py` 是 `gaia_bench/runner.py` 的简称、`web_search` 指通道而非工具调用），
  **零动作轮上的违例 6 → 0**；`completion` 27,690 → 13,638（推理 25.7K → 11.6K，非受控对照，
  仅记 observation）。取证：`docs/notes-contract-rehearsal-20260917.md`、worklog §138。
- **执行者标签的第二用途：路由与咨询的索引**（用户口径 2026-09-17）。它不只是"这轮是谁写的"
  ——主 agent 转交任务、agent 之间找人问细节，都要靠它知道**谁更深入了解哪一块**。
  故除职责表（**声明态**：注册表说谁负责什么）之外，另由代码机械派生一张
  **`[执行者索引]`（事实态）**：谁碰过哪些文件 → 哪几轮，零 LLM、从分块直接算，
  不采信模型的说法。两者对不上时，本身就是信号（声明了却没碰过 / 碰了却没声明）。
  **注意覆盖面**：这张索引的完整度**等于文件表的质量**——本场 4 个域没有文件，
  它们就不出现在索引里（这正是 §3.3"文件表必须完整、缺一个就是缺陷"的又一条理由）。
- **机械校验分两档**：**硬门**——零工具动作轮的产物不得出现文件路径或工具名（无歧义、
  无假阳性），违者带诊断重发一次；**软提示**——其它轮提到本轮没出现过的路径/工具只留痕
  （可能是合理简称或跨轮引用），不拦。
- **节奏：攒着一次性写**（2026-09-17 用户口径："你咋不考虑攒着一次性整理呢？其比每轮
  整理省了重复的输入"）。**触发沿用今天的水位**（+ 宽限 + 冷却），一批轮一次调用——
  每批只付一次"重读整段"（`h×C`），每轮各发一次要付 N 次（实测 N=9 时约 3 倍）。
  契约缩到"一句话/轮"后，攒批不再有今天的失控风险：今天的畸形全是**大产物**的病
  （逐块描述 + 全量 state_patch 12K+ → 截断/块 ID 错位/轮缺失），不是"注意力不集中"的病。
- **喂法：统一全量纯追加，不择路**。`甲 < 乙 ⟺ h·C < R`，而 h ≈ 0.02（用户口径）
  → `h·C ≈ 4K`（200K 上下文），除了一轮比 4K 还小，全量都是赢的；而那种小轮
  省下的绝对值只有几千等效 tok。**多一条分支不值得，删掉。**
- **时机**：note 落地随时可以（在换档之前没人读它）；**只有 `folded` 标志的推进必须落在
  "无开放轮"的边界**（§6.3）。不必"立刻发"——前缀缓存实测 24 小时有效，
  初稿写的"TTL 过期"是误判（§4.1 已更正）。
- **失败与幂等**：`note_state ∈ pending/done/failed` 落盘可见；一轮一条、重跑覆盖；
  进程退出前扫一遍补齐（同 `organize_backlog(force=True)` 语义）。
- **它服务两个消费者**：给人看的叙事（人机协同，UI 现在正缺）+ 给 agent 的公共段。
  **一次产物喂两个消费者 → 那一步不是成本**。

### 3.3 文件是唯一归属

- agent 对自己的文件**完全可编辑**；别人的文件**只读**，需要细节就**问**。
- 归属**机械计算**（现有 `_bind_files_by_path` 已经在做这件事，新方案里它从"顺带"变成"唯一"）。
- **文件表必须完整**：缺一个就是缺陷、当场补，**不许兜底给主 agent**（兜底给 main 是本场
  所有毛病的源头之一）。

### 3.5 取回细节：检索 / 窗口 / 地图（**已实现**，2026-09-17）

折叠只降分辨率、不删事实，所以必须有取回通道。但取回的形态**不是"展开一轮"**：
一轮可以有多大，本场实测给了数——`R2` 一轮 **260 个事件 / 229,285 字符**（≈16 万 tok），
整轮倒出来就是一次灌满上下文。故 `expand_history` 改成三种用法：

| 用法 | 调用 | 返回 |
|---|---|---|
| ① 检索 | `pattern="正则"`（可配 `scope` / `source` / `offset`） | **命中清单 + 总数 + 续取指针**，一次只列 5 处 |
| ② 看窗口 | `ids="R3-E02"` + `around="关键字"`（或 `offset` 续读） | 该处**窗口**（默认 800 字符，尾部给续读 offset） |
| ③ 看地图 | `ids="R3"` + `level=summary/truncated` | 该轮块视图 / 事件索引（先看地图再取细节） |

* `scope` 收范围：`R3-R8`（轮区间）或 `file:gaia_bench/runner.py`（只在该文件被读写过的事件里找，
  与 §3.3 的文件归属表对齐）；`source` 收来源：`result`（工具结果）/ `assistant`（模型正文）/
  `call`（工具调用）/ `user`（用户发言）——**分开列才不会让"哪次调用用过这个工具"淹没
  "工具结果里的那条结论"**。
* **轮级 `level=full` 已退役**：改为返回"本轮 N 个事件 / M 字符 + 检索入口"，不再整轮倒出。
  事件/块级的 `full` 保留（单事件实测 p50 547 / p90 1,891 / max 15,437 字符，有界）。
* **0 命中必须说清"这不等于历史里没有这回事"**——与检索那条线"网上没资料"的错误结论同源。
* 结果作为**工具结果追加在尾部**，不改历史字节（前缀纪律自动满足）；取回的细节进**私有层**，
  要变成共享结论走 §11 回写。
* **每次取用都记账**（模式 / 命中数 / 返回体量，`task.history` 的 `expand` 项）——上限与默认窗口
  "暂时不设置，有数据了再说"（用户口径），先用 `limit=5 / 每处 120 字符 / 窗口 800 字符` 跑。

### 3.6 分裂：只按活性文件画树（**已演练**，2026-09-17）

用户口径："只需要管活性文件的结构树即可。其它一律不用管。不需要管用户块了，环境了，什么什么
保底了。"于是分裂的输入输出缩到最小：

* **输入**：活性文件清单（路径 + **首行说明**，代码取，模型不抄）——没有块地图、没有用户块/
  环境块/保底块、没有非 LIVE 文件挂载、没有重组上下文；
* **输出**：结构树（节点用 `path`/`paths` 声明范围）+ **顶层节点职责**；
* **其余全由代码算**：文件归属按**最深的 path 前缀**、文件级描述取文件开头、非 LIVE 文件挂载、
  块归属——一律不问了。

演练仪器：`scripts/rehearse_split_live_files.py`。本场实测（11 个活性文件）：

| 项 | 读数 |
|---|---|
| 输入 | 1,186 字符 / `prompt 1,020`（cached 512） |
| 输出 | 16 节点，3 个顶层（`gaia_bench` / `gaia_findings` / `prompt_review`），各带三件式职责 |
| 代码机械绑定 | **覆盖率 11/11** ✓（最深的 path 前缀，无一个没人认领） |

对照现状维护的分裂调用（prompt 230,361 / 12K 级产物、还带 org 那一跳），这一版是**两个数量级**
的缩减——而且产物更干净（没有块归属、没有兜底桶、"树与上下文不一致"这一类问题从输入侧就不存在）。

#### 反例与修法：过度分裂（2026-09-17 用户口径）

第一版演练把 `output/gaia/FINDINGS.md` 单列成一个顶层域（`gaia_findings`），用户指出这是
**过度分裂**："写这个需要 gaia 的内容，且很多……那这个 agent 不是得频繁与 gaia 交流或者读其
文件了"。缺的判据是"**这个域能不能独立接活**"——不是"这个文件在不在单独的目录里"。

修法两条：

1. **指令补第 5 条**：`docs/`、`output/` 这类**目录名不是职责**；**一个文件的产出工作属于谁，
   它就归谁**（写 FINDINGS.md 要读 GAIA 的全部内容、是跑完评测后的汇总 → 归 GAIA 域）；
   自查一句"**这个域要干活时，是不是得频繁去读别的域的文件、或频繁问别的域？** 是 → 别拆"；
   顶层域一般是"**一个有产出的工作线**"，不是一个文件。
2. **机械耦合检查**（零 LLM，代码算）：**同一轮里一起被碰过的文件，是"同一域"的证据**。
   单文件顶层域若与别的域共享轮次，就是过度分裂。对**旧树**跑这个检查，当场抓到：
   `⚠「gaia_bench」与「gaia_findings」在 R2 里被一起碰过 → 疑似应合并`——证据是 R2 同一轮里
   既写了 `gaia_bench/*` 又写了 `output/gaia/FINDINGS.md`。

**修后重跑**（同一场、同一批活性文件）：

| 项 | 修前 | 修后 |
|---|---|---|
| 顶层域 | 3（`gaia_bench` / `gaia_findings` / `prompt_review`） | **2**（`GAIA 评测 harness` = gaia_bench/ ＋ output/gaia/FINDINGS.md；`系统提示词审查` = docs/prompt-review-*.md） |
| 节点数 | 16 | 2 |
| 覆盖率 | 11/11 | 11/11 |
| 耦合检查 | — | ✓ 无跨域共现；单文件域只剩「系统提示词审查」（它确实由自己那条线独立产出） |
| completion | 3,795 | **1,133** |

代价是**树变平了**（没有中间层）。中间层属于"结构展示"，可以交给**代码按目录自动生成**（零 LLM）
——模型只负责回答"哪些是职责域"，层级展示不必它操心。

**留给后续拍板的两个旋钮**（都不影响本版能跑）：

1. **树深度**：带首行说明时模型给出 per-file 叶子（16 节点）；不给说明时只给 8 节点。
   深浅都可以（归属按最深前缀仍唯一），要不要在指令里收一句"层级到能说清归属即可"由你定。
2. **顶层粒度**：单文件域要不要当顶层，**提示词里给判据（能不能独立接活）+ 代码给机械检查
   （同轮共现）**，最终"值不值得建 agent"仍由 `economics.split_benefit`
   （`(B−B′)×N_future − 18,830 > 0`）说了算：树只管**结构**，拆不拆由算式说。
3. **中间层**：要不要恢复"该深就深"的结构展示？建议交给代码按目录生成（零 LLM），
   模型只回答"哪些是职责域"。

### 3.7 读过的文件变了：把行级差异注入到轮首（**提案**，原料已齐）

用户口径（2026-09-17）："读文件后，如果发生改变，下次输入指令时，将其当作提示，注入到用户内容
上面，告诉其之前读过的文件进行了修改，修改了哪些行。方便其快速少量的更新。"

**为什么值得做**：现在这件事只有"写到一半才发现"的版本——`tools/files.py::_stale_error` 在
写入时发现文件已被外部改过就**拒绝执行**，补救动作是"重读整个文件 + 重来一次调用"。
把它提前到"下一次开口就告知"，而且给的是**行级差异**而不是"重读全文"。

**原料全在仓库里**（不用新造）：`_file_registry` 记录观察到的 `(mtime_ns, size)`；
`.wovra/history/<路径替换 __>/<时间戳>.bak` 存着每次覆盖/编辑前的旧内容（`_HISTORY_KEEP=10`）
——**那就是 diff 的原料**；`difflib` 是 stdlib。实测渲染（真实归档 vs 真实文件）：

```text
[文件变更] gaia_bench/runner.py　你在上次观察之后它被改过：+5 −0 行（243 → 248 行）
@@ -145,2 +145,7 @@
     tasks = gdata.load("validation", level=args.level)
+    if args.ids:
+        …（4 行）
     if args.offline_only:
（该文件共 5 份历史版本，更早的改动可能也影响你手里的内容）
（只要改动处就够用，别整文件重读；要全文再 read_file）
```

**顺带查出一个真缺陷（多 agent 下会漏检）**：`_file_registry` 是**进程级全局**的。
V4 分流后同进程里多个 agent 共用它 → **B 写文件会刷新这份记录**，于是 A 手里那份旧内容在记录上
看起来"是最新的"，`_stale_error` 不会触发。所以要做这件事，必须把它改成**按 agent（按视图）
的观察记录**。

**注入位置与硬约束**：注入在**轮首、用户消息之前**——那一段本来就是"要追加新字节"的区域，
**不会作废任何已有前缀**（与"高频状态放尾部"是同一条纪律的两端：都在追加区）。
**轮内冻结**：通知在轮开始时算一次，轮中不重算（否则轮次中部改字节，撞 AGENTS.md §2）。

**内容与上限**（建议）：只给 hunk（默认 ≤14 行）+ `+a −b 行` 计数；有多份历史版本时补一句
"更早的改动可能也影响你手里的内容"；末尾固定"够用就别整文件重读"；同一文件多次改动合并或
只报最新一次 + 计数。

**外部编辑也留副本，并标明"这是用户操作"**（2026-09-17 用户拍板）。落法：

* **观察快照（内容寻址）**：`.wovra/observed/<路径替换 __>/<hash>.txt` —— 每次 agent 观察
  （读或写）某文件时存一份，**与 `restore_file` 的版本档案分开**（那个是"可回滚的旧版本"，
  这个是"你上次看到的内容"，目的不同，别混淆）。内容寻址天然去重。
* **通知 = diff(你的观察快照, 当前内容)**，谁改的由日志判：有工具写入记录 → "工具（某个 agent）"；
  没有 → "**用户操作**"。
* **用户操作的措辞不预判对错**（用户口径原话："可能无操作，例如多加了一个符合导致的报错，
  或者误删，但同时也有高质量的修改的可能"）：

```text
[文件变更·用户操作] gaia_bench/runner.py（你的观察副本 …）
  改动：+1 −1 行（248 → 248 行）
  **这是用户操作，不是工具写的**——可能是有意的高质量修改，也可能是不小心的（例如多加一个
  符号导致报错、误删了一段）；**不要当成权威版本，也不要当成错误**，先看差异再决定：
  顺着它改、改回去、还是先问一句
@@ -150,3 +150,3 @@
-    if args.offline_only:
+    if args.offline_only
```

**注入位置（已定）**：**轮首、单列一条 `<runtime-reminder>[文件变更]</runtime-reminder>`**，
不塞进尾部的文件地图节。三条理由：① **生命周期不同**——尾部信封是"每步都可能变的状态"
（todo/账本/文件地图），这条是"轮开始算一次、**轮内冻结**"的一次性提醒，混在一起会让两种纪律
纠缠；② **语义不同**——地图是**全局清单**（有哪些文件、归属谁、在哪些轮被碰过），这条是
**针对收件人个人的过期警告**（"你手里那份过期了"）；③ **位置匹配行为**——它管的是"你正要开始
干的这轮，手里文件已过期"，紧挨着用户请求读最有效（也正是"注入到用户内容上面"的原话）。
另外这个位置**不花钱**：轮首本来就是追加区，不作废任何已有前缀。

**一个边界**：它不替代重读，是**路标不是内容**（正文里固定一句"够用就别整文件重读"）。

**与"文件地图注入"（`core.py::_maybe_inject_file_map`）的关系**：那张图是**全局**的（有哪些文件、
在哪些轮被碰过、归属谁）；这条通知是**按 agent 的、内容级的**。一个管"存在与位置"，
一个管"你手里那份过期了"。

### 3.8 fork：未激活共享公共上下文，首次激活才分离（2026-09-17 用户口径）

**三条与现状一致的细节**：

1. **agent 层的取法**：树顶层若有 ≥2 个节点 → agent 就是顶层；**顶层只有一个就往下延伸**，
   直到某层 ≥2 个节点，**最低细到单个活性文件**（所以树该深就深——深了才有得延伸，§3.6 的
   "该深就深"到这里有了理由）。
2. **权限**：每个 agent 对自己名下文件**全部权限**；别人的文件**只读**（要细节走 §3.5 检索/窗口，
   或 §11 问）；**新建的文件归创建者**（机械：写事件的那个执行者）。
3. **编号机制不变**：沿用现有 registry id 与轮/块/事件编号。

**fork 语义**：

* **未激活的 agent 不持有自己的上下文**——它看到的就是**公共上下文**（零成本待命；N 个子 agent
  不是 N 份上下文）。
* **首次激活 = fork**：`[公共上下文（fork 时刻的快照）] ＋ [自己的职责]（＋ 本轮用户输入与转交说明）`；
  从这一刻起它**只追加**，成为自己稳定的前缀。
* **之后**：**自己干的那几轮全量**进自己的上下文；**别人干的轮只进那一轮的简述**（由该轮执行者
  写的段落，§3.2 的写）。公共上下文继续为"未来的 fork"服务，**不回灌已 fork 的 agent**。
* 例（用户原话的落法）：R1–R8 触发整理+分裂，**整理期间又聊了 R9–R10** → 处理完成时
  **公共上下文 = R1–R8 的整理产物（每轮一段＋账本）＋ R9–R10 全量原文**（批次冻结、批次外的轮
  不整理，§6.4）。分裂出 A/B/C：R11–R13 与 A → **A 在 R11 fork**；R14–R15 与 B → **B 在 R14 fork**；
  C 一直没被激活 → **始终没有自己的上下文**。

**Main 不 fork**（用户口径 2026-09-17）：Main 就是"**永久的公共上下文 + 路由职责**"，不给它私有
追加尾巴。公共上下文的压缩：**水位触发 → 折叠前面的对话，用户原话逐字保留**；**原文窗口取近 50 轮**
（水位优先——50 轮是"正常情况下保留的窗口上限"，若 50 轮的体量本身已超水位，折叠线可以继续往近处
推进）。

**子 agent 的压缩 = 回落，不是自己折叠**（用户口径 2026-09-17："子 agent 上下文达到水位，那其就
替换为公共上下文即可。然后激活时划分职责即可"）：达到水位 → **重置为"当前公共上下文 + 自己的职责"**，
继续往后追加。于是"折叠"这套机制**只有公共上下文有**，子 agent 不做自己的折叠线——好处是所有 agent
的压缩基线一致（不会各折各的、越走越偏）。代价是回落时它自己的旧轮细节不再留在上下文里，
靠三样东西兜：**文件是状态载体**（§3.3）、**账本是结论载体**（免裁剪档）、**检索/窗口能取回原文**（§3.5）。

**轮的简述一旦被读取就是固定的**（用户口径 2026-09-17："轮的简述以第一次被读取为终止"）：
被任何 agent 读过 → 冻结，此后不得改写。补一条：**代码骨架段不算 note**（它只在 `note_state=failed`
时留痕、不进任何人的上下文）——所以"骨架段后来被模型版本替换"也不构成"改写已读内容"。

**由此推出的四条机械规则**：

1. **fork 只在轮边界**——公共上下文必须是确定快照；轮中 fork 会让同一 agent 的两次调用看到不同
   前缀，撞 §2 硬线。
2. **别人的轮进我的上下文，以"其简述已产出"为前提**（简述还没写出来就先不进）——fail-safe，
   与 §6.3"缺 note 的轮不换档"同一条纪律。
3. ~~每个 agent 有自己的超龄线/水位~~ → **改为**：折叠只发生在**公共上下文**（Main 那条线，
   水位触发）；**子 agent 达到水位 = 回落到"当前公共上下文 + 职责"**（上一段的规则）。
   于是 `last_context_estimate` 仍是公共那条线的量，子 agent 另记自己的体量用于触发回落。
4. **registry 记 `forked_at`（轮号）**：零成本，且"谁什么时候独立的"本身就是审计线索。

### 3.4 每个 agent 的视角

```
系统提示词（常量）
 + 共享叙事（全体逐字节相同，含执行者自己那几段）
 + 自己的文件范围 + 自己的私有细节
```

**不做"其他 agent 的上下文尾部注入"**：共享叙事里每段都带执行者，这已是跨域最小视图；
真要细节走"只读文件 / 问"两个出口。

## 4. 成本账（分流，不是并行）

**前提：现在是分流——一轮只有一个执行者，不是并行。** 由此：

- **公共段是"复用"不是"复制"**：每轮只有一个请求，公共段在那个请求里出现一次，逐字节与
  上一轮相同 → 跨轮命中缓存。**不是 N 个 agent 各存一份。**
- **空闲 agent 冻结**：不干活就不发请求，上下文不增长（这也是"子 agent 不会出现断裂性
  上下文"的来源）。
- 执行者手里的**细节**与公共段里**那段话**是两样东西，不构成重复。
- **真正重复的只有两样**：
  1. 多写一次总结 —— 但它服务人与 agent 两个消费者，**不计入浪费**；
  2. 执行者自己那几轮"段落 + 细节"并存 —— **故意保留**：为了让公共段对所有 agent
     （含执行者自己）逐字节相同。**不许为省这点 token 按身份裁剪公共段**（会断公共前缀）。
- **成本中心是"重写公共段"**（整理生效 → 一次全局断前缀），不是"复制公共段"。
- **并行不提前优化**：真到两个域同时干活那天，公共段才会同时出现在 N 个请求里，
那时才轮到"公共段要瘦"。先记一笔。

### 4.1 喂法的缓存账（2026-09-17 受控实测）

仪器：`scripts/probe_settlement_cost.py`（常驻；`--cut` 跑截断形态）。取证落
worklog §133。受控前缀、不依赖任何真实会话（真实会话中途改提示词/工具数组会
打断前缀，读数不可用于方案对比）。

| 形态 | prompt | cached | miss | 命中 |
|---|---:|---:|---:|---:|
| 甲 纯追加（第 2/3 次） | 40,545 / 40,555 | 40,320 | **225 / 235** | 99.4% |
| 乙 另起一条流（原样重发） | 20,571 | 20,352 | 219 | 98.9% |
| 砍尾部 1..7 + 指令 | 37,521 | 37,376 | 145 | 99.6% |
| **砍开头 5..9 + 指令** | 26,811 | **0** | 26,811 | **0.0%** |

* **缓存只能从第 0 个 token 起逐字节匹配连续前缀**：砍开头 = 整条输入按未命中价
  重付；砍尾部仍是前缀，命中。想在中间删内容又要命中，唯一时机是**换档那一刀**
  （那时本来就要重建前缀）——与 AGENTS.md §2 同一条纪律。
* 成本口径：**等效未命中 tok = miss + h × cached**（h = 命中价 ÷ 未命中价）。
  命中率高 ≠ 便宜：成本主力是 `h×整段`（**每批一次**，随会话增长）加产物输出。
  `甲 < 乙 ⟺ h·C < R`：h ≈ 0.02（用户口径）、C=200K 时门槛只有 4K，故
  **全量（甲）几乎通吃**——择路分支不成立（见 §3.2）。
* 端点（`api.commandcode.ai`）**测不出 h**：usage / 响应头 / metadata 三处都不给金额，
  `/models`、`/user/balance`、`/usage` 全 403，`cache_write_tokens` 实测 `null`。
  h 以用户口径为准（**0.02**）。
* **更正（同日）**：本文件初稿写过"254 分钟空档 → TTL 过期作废 96,300 tok"。
  那次是**用户改系统提示词**（前缀首部变了 → 整段失效），不是空闲过期；
  `probe_cache_hits` 的"空闲过期"是**启发式归类**，当时没核实就写进了文档。
  前缀缓存有效期按用户实测为 **24 小时**，故攒批不受"必须立刻发"的约束。
* **练兵实测（新契约真跑一次，见 `docs/notes-contract-rehearsal-20260917.md`）**：
  会话 `20260916-090533-964be8` 全 9 轮。输入 `prompt 131,523`（本次全 miss——练兵前缀是

  推论：契约缩小省的只是产物那一块；而**调用次数**（每次都有推理开销）比"重复输入"

* 一句话的实际长度 ≈ **195 字符/轮**（1,758/9）→ 200 轮约 39K 字符 ≈ 30K tok，

## 5. 压缩与恢复

### 5.1 按"恢复成本"分档（用户口径）

| 档 | 判据 | 压缩成什么 |
|---|---|---|
| 0 常量 | 与轮次无关 | 原样常驻（信封） |
| 1 cheap & 确定 | 一条命令/一次读就拿回（活性文件现状、成功的环境事实） | **指针 + 角色 + 指纹 + 承载的结论**，不抄内容 |
| 2 昂贵/不确定 | 重跑要钱要时间，或结果不再一样（跑评测、抓网页） | **结论 + 关键数字 + 复现命令**，原文落盘 |
| 3 不可恢复 | 盘上已没有 / 世界不会重来（非 LIVE 文件承载的中间信息、**失败的环境配置**） | **它是什么 + 验了什么 + 为什么没了**，**免裁剪** |

补两条修正：

- 活性文件的**内容**可丢，**动机与取舍**不可丢（文件只呈现最终状态）→ 档 1 必须带"它承载了
  哪些结论"。
- 成功的环境配置压成**一行可验证的状态**（"依赖已装（uv sync 成功）"）——一行比"再跑一次
  验证命令"便宜；**不可验证的一次性事实**（手工配的路径、口头授权）必须留全。
- **负面知识（失败与坑）体积最小、价值最高**：`known_issues` / `constraints` /
  `open_questions` 设**免裁剪档**并带来源轮次。

### 5.2 共享叙事自身也要分层（防膨胀）

一轮一段话，两百轮就是两百段。分层：

```
近若干轮   ：一轮一段（原文级）
更早       ：按主题/阶段合成一段（一段覆盖那几轮）
再早       ：只留存在性清单 + 指针（有哪些文件、跑过哪些实验、产物在哪）
原文       ：按轮落盘，随时可取回
```

判据仍是那条不对称原则：**内容可以压，存在性不能丢**。

## 6. 触发与节奏（写攒批、换零成本）

"写"和"换"是两个动作，但**节奏可以一致**：一批轮攒到水位，一次调用把它们的段落写出来，
紧接着换档零成本地读它——这比"每轮各写一次"省掉 N−1 次整段重读（每次 `h×C`）。

### 6.1 写：沿用今天的水位触发，攒着一次性写

**触发条件不改**（`WOVRA_ORG_WATERMARK` + 宽限 3 轮 + 冷却 3 轮，见 `_maybe_organize_batch`）：
一批未整理轮一次调用，尾部追加指令，产出"这批每轮一句话 + 账本增量"。改的只是**契约**
（逐块描述 + 全量 state_patch → 一句话 + 账本增量），产物 12K+ → ~1K；今天那批失败模式
（畸形/截断/块 ID 错位/轮缺失）都是大产物的病，契约一小就没了。

**不新增触发旋钮**。只有当实测发现段落质量不达标（一批内的轮之间串味）时，才把节奏降到
"每轮一次"——那只是改触发频率，不动其它机制。

### 6.2 换（装配换档）

| 条件 | 作用 |
|---|---|
| 水位（现有 `WOVRA_ORG_WATERMARK`） | 代价大时立刻整理 |
| **轮次上限**（新增，缺） | 给"最坏情况下多久换一次"兜底，防连续小轮迟迟不触发 |
| 惰性空隙 | 轮边界且无未闭合轮时顺手换，不打断用户 |
| 主题切换（可选） | 换话题时顺手换，边际成本接近零（本来就要断一次前缀） |

轮次上限的取值**不拍脑袋**：用 §4.1 的口径算 `(换前体量 − 换后体量) × 剩余轮数 − 18,830 > 0`
（复用 `economics.split_benefit` 同款算式）。

### 6.3 三条机械保证（让"迟到/缺失"不出事）

1. **档位在轮闭合时判定并落成标志**（`r["folded"]`），渲染只读标志、不每请求重算
   → note 迟到也不会在轮次中部改字节（AGENTS.md §2 硬线由此天然满足），
   且**不需要暂存区 / promote / 指纹核对**——note 只在换档那一刻被读。
2. **一次换到位**：断点 = 第一个被换的槽，要重发的是断点之后的全部（§4.1：砍开头 = 0 命中）。
   逐轮换会把原文窗口整个重发一遍，又勤又贵；一次换到位后尾部只剩"原文窗口 + 当前轮"。
   超龄线**轮内冻结**，只在轮闭合推进。
3. **缺 note 的轮不换档**（fail-safe：宁可多花 token，不丢内容）——它继续按原文顶着，
   只有成本、没有正确性风险，且 `note_state=failed` 让它在账面上可见（今天的盲区正是"没有
   机械信号"）。

### 6.4 异步错位：整理期间新闭合的轮怎么办

触发那一刻**批次就冻结了**（`_org_inflight` 已在做），产物**按轮键控**（每轮一段），所以
整理期间新闭合的轮（R11、R12）天然不在产物里——**全量保留原文装配，等下一批**，
**不需要任何特例**：它们本来就在"原文窗口"内（§6.2 的 `FOLD_KEEP_GENERATIONS` 语义），
异步错位只是让它们多等一轮才进批次。

**实测换档的实价**（会话 `20260916-090533-964be8`，替换发生在 15:23:27）：替换后下一次调用
`prompt 13,908 / cached 7,808` → **断档只花 6,100 tok**，而上下文从 ~139K 掉到 ~14K。
机理：断点之后要按未命中价重发的那部分，正是**换完之后的那份短文本**——所以
**换得越彻底越便宜**，这是"一次换到位"的第二条理由。R11/R12 若在整理期间到达，会让这份
"重发"略大（它们按原文保留在尾部），但相对省下的 125K 可忽略。

异步错位的真风险只有两条，都要机械保证：

1. **全局标量被旧快照覆盖**：批次产物按"触发时刻的历史"算，落地时历史已走到 R12 →
   `current_status` / `goal` / `is_done` 会用旧结论盖掉新状态（今天的 `state_patch`
   就是这个形状）。→ **批次模型只产出 append-only 条目**（约束/坑/拍板/待决/完成）；
   **标量由代码从"最新一轮的 note"渲染**。
2. **结案越界**：`closed` 是唯一会"删"的操作，落到 R11/R12 刚加的条目上就是误删。→
   条目带序号，**序号 ≥ 批次起点的不可结**。

而"整批作废"这一类（今天实测会丢轮 → 判 `failed` → 回水位 → 再付一次 218K 输入的 `h·C`）
在新方案里不存在：note 逐轮独立提交，**缺哪轮补哪轮**。

时机规则：产物可随时落地（没人读它，直到被换档）；**只有 `folded` 标志的推进必须落在
"无开放轮"的边界**（硬线）；进程退出前补齐并落地（`organize_backlog(force=True)` 同款）。

**落实的四个机械保证**：① 谁写（模型写内容，代码保完整）；② 粒度（每轮一段 + 失败单独一行）；
③ 移出的原文去哪（按轮落盘 + 存在性清单 + 取回通道）；④ **验收断言**（见 §11）。

## 7. 与现状的取舍

**保留**：水位整理的触发思想、fail-closed（产物不可信就不落地）、前缀纪律
（只有整理生效才允许断前缀）、文件账本（live / read_only / dead）、权限守卫
（按归属限写）、spill 落盘 + `read_file` 取回、状态账本 7 列表。

**删除**（重组派生的一切）：
- `views.ownership` 的块归属判据链（含四条落 Main 的路径、"跟轮走"兜底）；
- "树里挂块"这套产物契约（节点不再需要 `block_ids` / `chat_block_ids`）；
- `active_view` 兼任"归属"的语义（它退回纯粹的运行时路由/粘滞状态）；
- `pending_view` 预备归属加速器（不再需要回填/预备）；
- 兜底桶"主 agent 收未认领"；
- **`pending_org` 暂存区 + `_promote_org_results` 生效点**：note 只在换档那一刻被读，
  改由轮闭合时落 `folded` 标志即可，**不需要暂存与 promote**（§6.3）；
- **org 的产物契约**（`block_summaries` / `refined_index` / 全量 `state_patch` 重写）
  → 换成"每轮一句话 + 账本增量"（§3.2）。

**替换**：语义块树 → **文件归属表**（agent ↔ 文件范围）+ **每轮一段话**。

---

## 8. 迁移路径（四步，每步可独立验收）

1. **段落契约 + 结算调用**：轮闭合后尾部追加一次调用（形态见 §3.2/§6.1），代码校验字段齐全，
   `note_state` 落盘；此时**不改装配、不改归因**——note 先只进 UI 与账本，
   装配仍走今天的 org。可独立验收：每轮必有一条、字段齐全、失败轮非空、幂等覆盖。
2. **换档改读 note，org 退役**：删 `pending_org` / `_promote_org_results`，改由轮闭合时
   落 `folded` 标志（§6.3）；每个 agent 的视图 = 共享段 + 自己文件 + 自己细节；
   删掉块归属判据链与兜底桶。此步之后，"树和上下文不一致"整类问题消失。
3. **触发与分层**：写/换节奏分离（§6.1/§6.2）+ 轮次上限触发；共享段按 §5.2 分层；
   存在性清单落地。
4. **删残余**：`pending_view`、`active_view` 的归属语义、旧产物契约字段。

## 9. 验收断言（机械可查）

- **公共段逐字节一致**：所有 agent 的共享段（含执行者自己那几段）字节相同。
- **每轮有段落**且字段齐全；缺字段当场退回重写。
- **文件归属完整**：每个文件（含只读/已删）都有归属，缺一个即缺陷（**不允许兜底给主 agent**）。
- **主 agent 无私有细节**（只接环境块与全局协调）。
- **跨线追问可答**：以本场 R4–R9 做回归——在"只有共享段 + 执行者标注"的条件下，
  R4–R9 的质问读得懂、答得出。
- **前缀**：每 agent 自身前缀只在自己尾部生长；命中率不降（对照本场 97.1%）。

---

## 10. 风险

- **跨线保真度**是这套设计的唯一真风险：分流到另一条线时，追问方手里只有那段话。
  出口是"只读文件 + 问"；因此**段落质量比段落长短更重要**。
- **总结质量**：执行者自写可能自我美化或漏坑 → 用固定字段 + 代码对账（失败项由 exit_code 强制）。
- **公共段膨胀**：靠 §5.2 分层压；原文始终在盘上，可回取。
- **迁移期两套并存**：§8 的四步要一步一验收，避免半新半旧。

---

## 11. "问"的纪律（分流架构下的唯一重复源）

- 跨域取细节走**问**（或只读别人的文件），一问一答各一小段。
- **问的答案要回写共享段**（至少一行结论 + 执行者 + 轮次），否则下一个空闲 agent 会重问一遍。
  这是分流下唯一会重复发生的浪费。
