# 上下文模型 v4：共享叙事 + 文件归属（草稿，待拍板）

日期：2026-09-16
状态：**讨论稿**。核心口径已与用户对齐，未决项列在 §12，拍板后再动代码。
驱动案例：会话 `20260916-090533-964be8`（GAIA 评测 + 提示词审查，9 轮、11 个活性文件）。

---

## 0. 一句话

**取消"重组"**：历史不再按域重切，只有**一份共享的压缩叙事**（每轮一段话，执行者自己写），
外加**域私有的细节**；唯一需要归属的是**文件**，而文件归属是机械的。
分裂从此不再"重切历史"，只变成"分配文件 + 建 agent"。

---

## 1. 分裂要解决的是什么（先定目标，再定机制）

**不是省 token，而是"注意力别被污染"**：解 A 问题时带着 B 的一堆内容，真正的代价是
**串味**——把 A 的框架和结论套到 B 上。

本场是活标本：模型一边捧着 GAIA 评测那一摊（九个脚本、260 个事件、跑批结果），
一边被问「你是不是不知道自己是 Wovra」；它把「测试 Wovra」理解成「搭 harness 去测那个平台」。
省 token 只是顺带收益。

由此，判据从"内容重不重要"改成"**它对当前问题是什么角色**"：

| 角色 | 判据 | 处理 |
|---|---|---|
| 前提 | 丢了这问题本身读不懂（R1–R3 之于 R4–R9 的质问） | **必留**（可压成一行结论/指针） |
| 参考 | 丢了不影响理解、影响结论质量 | 留**指针 + 结论**，细节按需取回 |
| 无关 | 既非前提也非参考 | 不留内容，**但留存在性** |

> **不对称原则（本设计的地基）**：**内容可以丢，存在性不能丢**。
> "不知道它存在"会让模型重新发明轮子、或得出"网上没资料"式的错误结论——
> 我们在检索那条线上刚踩过同一个坑。内容是可恢复的，存在性不可恢复。

---

## 2. 现状为什么不行（六条，均可复现）

1. **两套真相源**：模型的语义树 vs 代码的机械判据链；同一份历史在两个面板走不同规则 →
   "结构树没问题、上下文不对"是结构决定的，不是显示 bug。
2. **兜底桶承担"未知"**：判据链上有四条路径落到主 agent（环境块、文件未认领、
   保底块跟轮、其余），本质都是"不知道给谁就给它"。N 个域之后它把分裂的收益反向吃掉
   （本场 Main 装配 14,415 tok = 基准 100%）。
3. **"主 agent 不许有文件"这条检查被替换成了更窄的保证**：`maintenance.py` 里
   "事后校验 + 抛错中止"退场，改由 `_bind_files_by_path` 的**构造保证**承担——而那条保证
   只覆盖**活性文件**，只读/幽灵文件走 `history_files` 另一条路，`views.ownership` 的
   "文件块没域认领就跟轮走"是**渲染期**兜底，不在保证内 → 本场 R1 的幽灵块就进了 Main。
4. **判据是表层特征**（路径前缀、轮标记），而归属本质是语义的（能不能独立接活、能不能
   独立验收、上下文是否连续）→ 一个职责被按文件碎成四个域（数据与筛选/判分与重判/
   执行与调度/报告与文档），一条语义线被劈成两半。
5. **块切分按文件、不按话题**；用户块只有一个落点 → "一轮拆给几个 agent、用户发言两边都留"
   在当前数据模型里做不到。
6. **没有"树错了"的机械信号**：唯一的覆盖缺口检查被"兜底给主 agent"静默吸收——
   树 8 节点对 agent 2 个，系统自己是沉默的。

**共同病根**：算法之所以要算"块归谁"，纯粹是因为要给每个域**重新切一份历史**。
**取消重组，上面六条一起消失。**

## 3. 新模型

### 3.1 三层

| 层 | 内容 | 谁带 | 变化频率 |
|---|---|---|---|
| **常量** | 工作区、解释器、shell、任务状态 | 系统提示词/信封，全体 | 几乎不变 |
| **共享叙事** | **每轮一段话** + 执行者 + 轮次 | 全体（逐字节相同） | 每轮追加一段 |
| **私有细节** | 自己的工具结果、分析、文件全文、决策 | 只有该域 | 该域干活时才长 |

### 3.2 每轮一段话

- **粒度**：一轮 → 一段；**长短看步数看细节，不强求统一**（用户口径）。
- **谁写**：**执行者自己写**，在轮闭合前（细节还在它上下文里时）——最高保真、最低成本。
  对比现状：维护线程**事后回读**历史再压缩，又贵又容易失真（本场"13 块未被域认领"的误判即此类）。
- **字段表（建议）**：`执行者 / 轮次 / 做了什么 / 结论 / 失败与坑 / 触及文件 / 待决`。
  前四项模型写，后三项代码可机械对账（账本、exit_code、状态账本）。
- **它服务两个消费者**：给人看的叙事（人机协同，UI 现在正缺）+ 给 agent 的公共段。
  **一次产物喂两个消费者 → 那一步不是成本**。

### 3.3 文件是唯一归属

- agent 对自己的文件**完全可编辑**；别人的文件**只读**，需要细节就**问**。
- 归属**机械计算**（现有 `_bind_files_by_path` 已经在做这件事，新方案里它从"顺带"变成"唯一"）。
- **文件表必须完整**：缺一个就是缺陷、当场补，**不许兜底给主 agent**（兜底给 main 是本场
  所有毛病的源头之一）。

### 3.4 每个 agent 的视角

```
系统提示词（常量）
 + 共享叙事（全体逐字节相同，含执行者自己那几段）
 + 自己的文件范围 + 自己的私有细节
```

**不做"其他 agent 的上下文尾部注入"**：共享叙事里每段都带执行者，这已是跨域最小视图；
真要细节走"只读文件 / 问"两个出口。

## 4. 成本账（分流，不是并行）

**前提：现在是分流——一轮只有一个执行者，不是并行。** 由此：

- **公共段是"复用"不是"复制"**：每轮只有一个请求，公共段在那个请求里出现一次，逐字节与
  上一轮相同 → 跨轮命中缓存。**不是 N 个 agent 各存一份。**
- **空闲 agent 冻结**：不干活就不发请求，上下文不增长（这也是"子 agent 不会出现断裂性
  上下文"的来源）。
- 执行者手里的**细节**与公共段里**那段话**是两样东西，不构成重复。
- **真正重复的只有两样**：
  1. 多写一次总结 —— 但它服务人与 agent 两个消费者，**不计入浪费**；
  2. 执行者自己那几轮"段落 + 细节"并存 —— **故意保留**：为了让公共段对所有 agent
     （含执行者自己）逐字节相同。**不许为省这点 token 按身份裁剪公共段**（会断公共前缀）。
- **成本中心是"重写公共段"**（整理生效 → 一次全局断前缀），不是"复制公共段"。
- **并行不提前优化**：真到两个域同时干活那天，公共段才会同时出现在 N 个请求里，
  那时才轮到"公共段要瘦"。先记一笔。

## 5. 压缩与恢复

### 5.1 按"恢复成本"分档（用户口径）

| 档 | 判据 | 压缩成什么 |
|---|---|---|
| 0 常量 | 与轮次无关 | 原样常驻（信封） |
| 1 cheap & 确定 | 一条命令/一次读就拿回（活性文件现状、成功的环境事实） | **指针 + 角色 + 指纹 + 承载的结论**，不抄内容 |
| 2 昂贵/不确定 | 重跑要钱要时间，或结果不再一样（跑评测、抓网页） | **结论 + 关键数字 + 复现命令**，原文落盘 |
| 3 不可恢复 | 盘上已没有 / 世界不会重来（非 LIVE 文件承载的中间信息、**失败的环境配置**） | **它是什么 + 验了什么 + 为什么没了**，**免裁剪** |

补两条修正：

- 活性文件的**内容**可丢，**动机与取舍**不可丢（文件只呈现最终状态）→ 档 1 必须带"它承载了
  哪些结论"。
- 成功的环境配置压成**一行可验证的状态**（"依赖已装（uv sync 成功）"）——一行比"再跑一次
  验证命令"便宜；**不可验证的一次性事实**（手工配的路径、口头授权）必须留全。
- **负面知识（失败与坑）体积最小、价值最高**：`known_issues` / `constraints` /
  `open_questions` 设**免裁剪档**并带来源轮次。

### 5.2 共享叙事自身也要分层（防膨胀）

一轮一段话，两百轮就是两百段。分层：

```
近若干轮   ：一轮一段（原文级）
更早       ：按主题/阶段合成一段（一段覆盖那几轮）
再早       ：只留存在性清单 + 指针（有哪些文件、跑过哪些实验、产物在哪）
原文       ：按轮落盘，随时可取回
```

判据仍是那条不对称原则：**内容可以压，存在性不能丢**。

## 6. 触发（"定期"到底是什么）

现状是**水位触发**（涨到水位就整理），不是定期。建议改为**多条件、取最先满足者**：

| 条件 | 作用 |
|---|---|
| 水位 / 涨幅（现有） | 代价大时立刻整理 |
| **轮次上限**（新增，缺） | 给"最坏情况下多久整理一次"兜底，防连续小轮迟迟不触发 |
| 惰性空隙 | 轮边界且无未闭合轮时顺手整理，不打断用户 |
| 主题切换（可选） | 换话题时顺手整理，边际成本接近零（本来就要断一次前缀） |

**落实的四个机械保证**：① 谁写（模型写内容，代码保完整）；② 粒度（每轮一段 + 失败单独一行）；
③ 移出的原文去哪（按轮落盘 + 存在性清单 + 取回通道）；④ **验收断言**（见 §11）。

## 7. 与现状的取舍

**保留**：水位整理的触发思想、fail-closed（产物不可信就不落地）、前缀纪律
（只有整理生效才允许断前缀）、文件账本（live / read_only / dead）、权限守卫
（按归属限写）、spill 落盘 + `read_file` 取回、状态账本 7 列表。

**删除**（重组派生的一切）：
- `views.ownership` 的块归属判据链（含四条落 Main 的路径、"跟轮走"兜底）；
- "树里挂块"这套产物契约（节点不再需要 `block_ids` / `chat_block_ids`）；
- `active_view` 兼任"归属"的语义（它退回纯粹的运行时路由/粘滞状态）；
- `pending_view` 预备归属加速器（不再需要回填/预备）；
- 兜底桶"主 agent 收未认领"。

**替换**：语义块树 → **文件归属表**（agent ↔ 文件范围）+ **每轮一段话**。

---

## 8. 迁移路径（四步，每步可独立验收）

1. **段落契约 + 执行者自总结**：轮闭合前产出一段话（字段表见 §3.2），代码校验字段齐全；
   此时不改归因机制，只把"叙事"变成一等产物。
2. **取消重组**：每个 agent 的视图 = 共享段 + 自己文件 + 自己细节；删掉块归属判据链与兜底桶。
   此步之后，"树和上下文不一致"整类问题消失。
3. **触发与分层**：加轮次上限触发；共享段按 §5.2 分层；存在性清单落地。
4. **删残余**：`pending_view`、`active_view` 的归属语义、旧产物契约字段。

---

## 9. 验收断言（机械可查）

- **公共段逐字节一致**：所有 agent 的共享段（含执行者自己那几段）字节相同。
- **每轮有段落**且字段齐全；缺字段当场退回重写。
- **文件归属完整**：每个文件（含只读/已删）都有归属，缺一个即缺陷（**不允许兜底给主 agent**）。
- **主 agent 无私有细节**（只接环境块与全局协调）。
- **跨线追问可答**：以本场 R4–R9 做回归——在"只有共享段 + 执行者标注"的条件下，
  R4–R9 的质问读得懂、答得出。
- **前缀**：每 agent 自身前缀只在自己尾部生长；命中率不降（对照本场 97.1%）。

---

## 10. 风险

- **跨线保真度**是这套设计的唯一真风险：分流到另一条线时，追问方手里只有那段话。
  出口是"只读文件 + 问"；因此**段落质量比段落长短更重要**。
- **总结质量**：执行者自写可能自我美化或漏坑 → 用固定字段 + 代码对账（失败项由 exit_code 强制）。
- **公共段膨胀**：靠 §5.2 分层压；原文始终在盘上，可回取。
- **迁移期两套并存**：§8 的四步要一步一验收，避免半新半旧。

---

## 11. "问"的纪律（分流架构下的唯一重复源）

- 跨域取细节走**问**（或只读别人的文件），一问一答各一小段。
- **问的答案要回写共享段**（至少一行结论 + 执行者 + 轮次），否则下一个空闲 agent 会重问一遍。
  这是分流下唯一会重复发生的浪费。
