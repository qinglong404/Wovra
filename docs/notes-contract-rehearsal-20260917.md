## 执行者由代码盖章（2026-09-17 用户口径：一轮可能由数个 agent 完成）

用户提的："一轮对话由数个 agent 完成的，那每个 agent 不都只需要总结自己的吗"。落法两条：

1. **`executor` 不进 schema、不让模型自报**——由代码盖章（追加档 = 正在追加的这个 agent；
   批次档 = 该轮的 `active_view`）。理由是硬的：本会话的病根就是**身份错位**，
   让模型自报身份等于给它一次写错的机会，而代码知道的比它准。
2. **一轮多棒就多条**：交棒轮由每个参与者各追加一条（各自的执行者 + 自己那一棒的内容），
   指令里写明"只写**自己这一棒**做了什么；别的参与者的部分由它们各自追加，不要替它们写"。

**渲染规则**：该轮有多条（多棒）或执行者非 Main 时才显示 `〔执行者〕`——pre-split 阶段全是
Main，200 轮都挂标签只是噪音。

# v7（定稿）：轮内用户原话必须逐字承载

**用户报的缺陷**（2026-09-17）：*"R2 我中间中断了一次，说『含网络检索的先不做，当前网络检索工具可能还有些小问题。』然后后面的测试就没有测试网络检索，这个应该也需要吧，怎么在现在的内容中看不到。"*

**核实**：R2 事件里确实有两条用户消息（轮头 + 轮内追加），R3 也有（轮头 +「不是，你在干嘛？我不是说，测试完就停止吗？」）。而 v1–v6 的渲染只挂了**轮头**一条——轮内追加在折叠后就没了。根因：V4 契约写"用户原话由代码逐字承载"，实现只覆盖轮头；**旧契约其实有这一块**（`_ORG_TAG_INSTRUCTIONS`："用户块【用户块】：轮头之后的用户补充/修正输入，先保留补充原话，再附要点"），删分块地图时被一起漏掉。这两条属**前提档**：丢了它们，"为什么只跑离线子集""为什么这轮以被叫停收尾"都读不懂。

## 顺带修掉的一个度量 bug

"候选落进 failures"第一次报 **1/4**，是假的：产物把候选改写成了别的措辞（"被用户叫停强杀"），
而**候选自己的事件 ID 就是最强落点**。把 ID 计入匹配后：

| 日志 | 候选落进 failures | failures 条数 | 带有效 ID |
|---|---|---|---|
| v6 | 4/4 | 15 | 4 |
| v7（轮内原话） | 4/4 | 6 | 4 |
| v7（收紧匹配） | 3/4 | 10 | 3 |

**诚实边界**：同一材料、同一契约、连跑三次，**failures 条数 15 / 6 / 10（2.5 倍波动）**——
单次差异是随机性，不能当机制结论；但免裁剪档的条数值得进趋势监控（同契约重复 N 次看分布）。
另外"带有效 ID"的条数始终等于候选覆盖数（4/4/3）——**凡候选覆盖到的失败，产物都带上了 ID**。

# v4/v5：用"便宜的输入"换"昂贵的思考"

**思路**（用户 2026-09-17：「我发现好的结构提示，可以大大减少思考量」）：失败与结论原本要模型
从上百 K 的工具结果里**回忆**（R2 的失败信息埋在 101,796 字符里，其中 11,481 字符带错误特征），
这是纯思考；机械扫出来喂给它，任务就退化成"核对 + 改写"。输入按未命中价、输出（含推理）按
输出价，后者通常贵好几倍——**用输入换思考几乎总是赚**。

## 加了什么

* **失败候选**：按特征扫工具结果（越界/不存在/HTTP 4xx-5xx/工具报错/被中止/空占位），
  带**事件 ID**（`〔R2-E174〕后台任务 bg-2 已停止（exit_code=-9）`）→ 产物里的失败项可
  `expand_history` 回原文。契约改成"以候选为底逐条核对，候选没有但你知道的照样写"。
* **结论草稿**：本轮 `final_answer` 首段（≤320 字符），标注"改写成一句话，别照抄"。
* **边界规则**：*每条是这一轮自己的交班记录，不是这一批的总述；把某一条单独拿给没看过会话
  的人，他能说清这轮发生了什么*。
* **长度锚**：一句话 80–250 字符。
* **校验器修误报**：路径改后缀匹配（`FINDINGS.md` ⊂ `output/gaia/FINDINGS.md`，多个路径被
  `/` 串成一串也放行）；工具名只在**零工具动作轮**算硬门（R3 的 `web_search` 指通道，属软档）。
* **候选扫描器修误报**：排除纯读类工具（文件正文里的"不存在"字样）；执行类工具只在
  **exit_code≠0** 时才扫（否则成功命令 cat 出来的文档正文会灌一堆假候选）。
