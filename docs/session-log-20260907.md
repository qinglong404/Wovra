## 二、当日拍板的规则（改代码前先对表）

1. **只有整理才破坏前缀**。未整理轮永远全量原文进装配，分辨率损失只允许来自整理；三档滑窗废除（实测把缓存命中率砸到 49.9%）。窗口 90% 紧急折叠是唯一天花板。
2. **水位整理语义**：触发 = 最近一次装配估算（窗口口径）≥ 100K（`WOVRA_ORG_WATERMARK`）**且轮闭合**；2026-09-09 用户拍板批次上限删除——到水位一次性收编全部未整理轮（最老优先），不再分批；单后台 daemon 线程 FIFO，与主对话不冲突；产物写 `pending_org` 暂存区，**下一轮开启才生效**（本轮装配纹丝不动）；全程静默无播报。
3. **工作区 = 启动目录**。在哪启动 wovra，PROJECT_ROOT 就是哪（`WOVRA_WORKSPACE` 可显式覆盖）；仓库子目录回退规则删除。
4. **步数上限 60 = 安全网**，不是目标。超限抛 RuntimeError 但轮保持开放，`\c` 直接接着干。
5. **命令形态**：`\c` / `\continue` 续跑（不注入新用户消息）；裸 `\` 或 `/` 打印全部命令列表；**没有** `\继续` 别名（用户明确嫌不美观）。
6. **测试纪律**：测试创建的会话用完即删——已用 conftest.py 自动重定向 TASKS_ROOT 结构性根治；tasks/ 里只允许存在用户真实会话。
7. **不做的事**：todo 工具（计划两层论：计划属于思考层，落成工具反而僵化）；眼睛/screenshot 暂缓（但使用压力已记录在案）。
8. **多 agent 废除**：未来方向是上下文分化运行时（单线程轮换的 Agent = 注册表条目 + 上下文视图 + 路由规则），不是进程编排。
