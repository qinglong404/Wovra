# 受控现场实验：managed vs baseline（实验二）

目的：把 11 轮观察性对照（见 `docs/managed-vs-baseline-11rounds.md`）
升级为受控实验——用封闭任务书钉死工作量，用静态验收清单客观化质量，
用归一化分母（成本/通过数）对冲模型自由发挥。

## 实验设计

| 要素 | 规定 |
|---|---|
| 任务 | 固定任务书（见下），实现 4 个指定功能，禁止自由扩展 |
| 起始文件 | `fixtures/chat-page.html`（19,257 字符 / 1003 行，冻结版，sha256 前 12 位 `2adc5fd21ecba9e9`，还原自会话 fbd3e6 的 R2-E02 原始 write_file——四项功能均未实现的最初版本），每轮复制到独立运行目录 |
| 模式 | managed（实验组）vs baseline（对照组），`new_run.py --mode` 控制 |
| 次数 | 每模式 N=5，共 **10 次独立运行**（一次运行 = 一个全新会话 + 一次任务书输入；**不是**在一个会话里输入多次） |
| 顺序 | ABBA 交错对冲时段漂移：A1, B1, B2, A2, B3, A3, A4, B4, B5, A5 |
| 模型 | 同一模型同一参数；如服务商支持，temperature 设 0 |
| 中断处理 | 单轮失败/中断记为该轮未通过，不重跑替代 |

## 任务书（原样粘贴为每轮第一条输入）

> 请在 chat.html 上实现以下 4 个功能，逐一完成，不要扩展其他功能：
> 1. 语音朗读：AI 回复的操作区加 🔊 按钮，点击用浏览器 speechSynthesis 朗读该条回复，再点一次停止；
> 2. 导出对话：顶栏加 ⬇️ 按钮，把当前会话导出为 Markdown 文件下载；
> 3. 重新生成：AI 回复的操作区加 🔄 按钮，点击后用原用户消息重新生成回复并替换原回复；
> 4. 会话内搜索：加一个搜索框，输入关键词时当前会话内匹配的消息高亮。
> 完成后用系统方式打开页面供检查。

起始文件路径在 `new_run.py` 输出里给出（`experiments/runs/<task-id>/chat.html`）。

## 验收标准（写入任务 acceptance_criteria，逐条客观判定）

1. 语音朗读：AI 回复操作区有朗读按钮，使用 speechSynthesis，含停止逻辑
2. 导出对话：顶栏有导出按钮，用 Blob 下载当前会话的 Markdown 文件
3. 重新生成：AI 回复操作区有重新生成按钮，用原用户消息重新生成并替换
4. 会话内搜索：有搜索框，输入关键词时匹配消息高亮
5. 不引入外部 API 与外部依赖（无网络请求、无外部脚本/样式）
6. 页面结构完整可渲染（标签闭合、脚本无语法错误）

静态检查（`check_acceptance.py`）自动判定这 6 条。**起始文件的基线判定
是 2/6**（C5 零依赖、C6 结构完整通过；C1-C4 功能项全部未实现——这是
"能否从 2 推进到 6"的量尺）。**局限要明知**：静态结构检查客观但可博弈
（写出标记 ≠ 实现行为），因此每轮完成后另做 **2 分钟人工冒烟**（逐个
功能点一遍），主观异常记入运行目录 `notes.md`，不影响自动口径，用于
结果解读时的交叉核验。

## 流程（每次运行约 10-20 分钟，共 10 次）

**一次运行 = 一个全新会话 + 一次任务书输入。** 每次运行都必须从
"同一冻结文件、零历史"的起点开始——这正是不确定性的对策：任务书
只输入一次，本轮结束（AI 给出最终回答）即本运行结束。

```bash
uv run python experiments/new_run.py --mode managed --index 1
# 按输出提示启动 chat，粘贴任务书（唯一的一条输入），等本轮结束
uv run python experiments/check_acceptance.py experiments/runs/<task-id>/chat.html
# 人工冒烟 2 分钟，异常写 experiments/runs/<task-id>/notes.md
```

然后**重新执行 new_run.py 创建下一个全新会话**（新 task-id、新文件
副本、零历史），重复以上步骤，直至 10 次运行完成。

> **为什么不能在一个会话里连输 5 次？** 第二次输入时，上下文里已经
> 带着上一次的实现历史——你测的就不再是"机制对同一任务的开销"，
> 而是被前次污染的历史开销，这正是观察性数据里"自由发挥不公平"的
> 另一个来源。受控实验的每一点信息都来自同一干净起点的一次尝试。

## 指标口径

| 层 | 指标 | 来源 |
|---|---|---|
| 行为（客观计数） | 步数、read_file 次数、重读事件数（同路径同区间重复读）、expand_history 调用数 | task.json 事件流 |
| 经济（名义+等效） | 名义 total、等效输入（未命中 + 命中/30） | usage 行 |
| 产出（归一化分母） | 通过验收条数（0-6） | check_acceptance |
| **主指标** | **等效输入 / 通过条数**（单位验收产出的真实成本） | 上两者相除 |

时间（墙钟）不作为指标：延迟是服务端外生噪声；步数是它的确定性代理。

## 汇总

10 轮跑完后：

```bash
uv run python experiments/collect.py
```

输出逐轮指标表 + 两模式的中位数对比（主指标：等效输入/通过条数）。
